# V100-45 — Qwen3-Coder-30B-A3B as a coding writer on 16 GB

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** A 30B MoE at Q4 is 17.3 GB — larger than the card. How many expert layers must move to CPU before it loads, and what does each one cost?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-bench -m qwen3-coder-30b-a3b-q4_k_m.gguf -p 128 -n 32 -ngl 99 -ncmoe N -fa 0 -r 1
llama-cli -m qwen3-coder-30b-a3b-q4_k_m.gguf -ngl 99 -ncmoe 8 -c 4096 -n 180 -p "<coding task>"
```

**Results.**

| Experts on CPU | prefill tok/s | decode tok/s |
|---|---|---|
| 4–6 | OOM | — |
| 8 | 411.9 | 75.5 |
| 12 | 298.7 | 63.3 |
| 16 | 247.6 | 58.8 |
| 24 | 181.2 | 45.7 |
| 8 + FA | OOM | — |

Live generation at -ncmoe 8: correct CSV revenue function with `csv` module, docstring and error handling, 76.7 tok/s.

**Repeats.** single run per configuration; three live generations

**Verdict.** Working configuration is `-ngl 99 -ncmoe 8 -c 4096`. An 8192-token context needs more VRAM (compute buffer allocation fails), so long files require either 12 CPU layers or a smaller context.

**Result type.** Positive.

**Does not show.** Code quality was judged on three prompts, not a benchmark. No comparison against the same model with all layers on a 32 GB card.
