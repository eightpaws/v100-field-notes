# V100-90 - FlashQLA legacy Gated DeltaNet kernel on Volta

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 24 vCPU, 94 GiB RAM._

**Question.** `weicj/FlashQLA-SM70-SM75` adds a forward-only SM70/SM75 backend for Gated DeltaNet on top of
a Hopper-only kernel library, and its README explicitly refuses to claim runtime numbers for SM70 "before
V100-class validation". Does the kernel execute on the V100, and is it correct?

**Environment.** V100-SXM2-16GB (sm_70), CUDA 12.9, torch 2.10.0+cu128 from the vLLM venv. The package
refuses to import on anything but sm90, so two guards were bypassed deliberately: `chunk/__init__.py` and
`chunk/cp_context.py` both `raise ValueError("FlashQLA now support sm90 only.")`, and both were replaced
with `None` so the shipped legacy entry point `chunk_gated_delta_rule_fwd_legacy` becomes reachable.

**Commands.**
```
python -m pip install -e . --no-deps --no-build-isolation     # in /root/flashqla
export PATH=/home/hermes/venvs/vllm/bin:$PATH                 # torch needs the ninja binary
TORCH_CUDA_ARCH_LIST=7.0 python v90_bench.py
```
The harness builds the kernel through torch's cpp_extension, compares it against a sequential PyTorch
reference (the same loop the project's own test uses) and times both.

**Repeats.** Correctness on one shape; timing is the mean of 5 iterations after 2 warm-ups with a
`synchronize` before and after.

**Result.** The kernel runs on the V100 and is **exact**: for batch 1, 512 tokens, 2 query heads,
4 value heads and dim 128 the maximum absolute difference against the reference loop is **0.0**. Timing:
**0.5 ms** for the kernel against **575 ms** for the sequential loop, a 1099x gap, with a 15 MiB peak.

That 1099x is against a Python loop, not against a competent baseline; it proves the operator executes on
the GPU rather than falling back to the CPU, which is what the README leaves open.

**Verdict.** Mixed, and the useful half is positive: the first V100-class validation the project asked for
now exists - the SM70 kernel compiles, runs and matches the reference bit for bit. The card's own criterion
(a 25 % end-to-end gain on a hybrid model) could not be tested, because neither llama.cpp nor Strata calls
this operator: it is a PyTorch-level kernel, so an end-to-end number needs a framework that wires GDN
through it.

**Result type.** Unstated - the result reports measurements without an explicit pass/fail verdict.

**Does not show.** No end-to-end measurement, no comparison against a tuned CUDA or Triton baseline (only
against a Python loop), and no long-sequence shapes beyond 512 tokens. The two `sm90 only` guards mean the
upstream high-level API still refuses to dispatch on this hardware.

**Raw.** `raw/runs/V100-90.json` - guards, build flags, correctness, timing, VRAM.
