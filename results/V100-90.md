# V100-90 — FlashQLA-SM70: Gated DeltaNet

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** `weicj/FlashQLA-SM70-SM75` adds a forward-only backend for hybrid linear attention (Gated DeltaNet) on SM70/SM75. If linearly-hybrid models (Qwen-Next, Inkling) are the basis of coding, without such path they will be slow on Volta.

**Environment.** V100-SXM2-16GB (sm_70), driver 580, CUDA 12.9, torch 2.10.0+cu128 from venv vLLM, `TORCH_CUDA_ARCH_LIST=7.0`.

**Commands.** ``` python -m pip install -e . --no-deps --no-build-isolation in /root/flashqla; TORCH_CUDA_ARCH_LIST=7.0 python v90_bench.py. ```

**Artifacts.** [raw/runs/V100-90.json](../raw/runs/V100-90.json) (guards, build flags, correctness, timing, VRAM)

**Repeats.** Correctness on one form; Timing - average of 5 iterations after 2 warm-ups.

**Result.** The V100 core executes and is accurate with a maximum deviation from the reference cycle of 0.0 on the form 1x512x2hx4kvxd128, time 0.5 ms compared to 575 ms for the Python cycle (1099x - against the cycle, not against the optimized baseline), VRAM 15 MiB. The card criterion (throughput gain of 25% on the hybrid model) cannot be verified: neither llama.cpp nor Strata invoke this operator. The high-level API still fails on sm_70: two guards `sm90 only` are bypassed manually.
