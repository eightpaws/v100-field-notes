# V100-95 - What a 4060 Ti can do that a V100 cannot

**Question.** Ada (sm_89) has bf16, FP8, Marlin INT4 and native flash-attention; Volta has none of these as hardware features and cuDNN convolutions do not run on this build (V100-54). Does that translate into tasks the desktop card does better, or is the rule still "inference stays on the V100"?

**Environment.**

| | Desktop | V100 guest |
|---|---|---|
| GPU | RTX 4060 Ti 16 GB, cc 8.9 | Tesla V100-SXM2-16GB, cc 7.0 |
| Driver | 617.14 | 580.178.04 |
| OS | Windows 11 | Ubuntu 24.04 |
| Engine | Ollama 0.40.17 | Ollama 0.40.16 (cuda_v12 libs) |
| Model in VRAM | 4.43 GiB | 4.58 GiB |

Model on both sides is the same file: `qwen2.5-coder:7b`, Q4_K_M, digest `dae161e27b0e`. A second model (12B, 7.35 GiB) was resident on the desktop card during the runs.

**Commands.**

```
python3 b95_speed.py http://127.0.0.1:11434 qwen2.5-coder:7b <out>.json 3 256
python3 b95_ctx.py   http://127.0.0.1:11434 qwen2.5-coder:7b <out>.json 2 300 64   # num_ctx 16384
python3 b95_worker.py --tasks v100_97_tasks.json --ids 0-19 \
    --base http://127.0.0.1:11434 --model qwen2.5-coder:7b --out <out>.json
```

On the V100 the same lines were wrapped by `/root/bin/v100-run.sh V100-95 -- ...`.

**Results.**

| Metric | V100 16 GB | 4060 Ti 16 GB | Ratio |
|---|---|---|---|
| Decode, 3522-token prompt, 256 tokens out | 103.1 ± 0.0 tok/s | 54.0 ± 0.25 tok/s | V100 1.9x faster |
| Prefill, 3522-token prompt (cold) | 3429 tok/s | 10789 tok/s | PC 3.1x faster |
| Prefill + TTFT, 8513-token prompt (cold) | 3321 tok/s, 2.56 s | 3516 tok/s, 2.42 s | equal |
| MBPP, 20 tasks, temp 0 | 15/20 = 0.75 | 14/20 = 0.70 | equal |

Total response time for the mid-context case (3522 in, 256 out): 3.5 s on V100 against 5.1 s on the desktop, so the prefill win is eaten by decode.

**Repeats.** Decode and prefill: n=3, mean ± stdev (stdev 0.0 and 0.25 tok/s). Quality: single run, 20 tasks, fixed seed.

**Verdict.** Mixed: the desktop card pre-fills faster at mid context and equals the V100 at 8.5k tokens, but decodes 1.9x slower, so no tested task finishes sooner on it. Inference stays on the V100; the desktop card is useful only where Volta lacks the hardware - and that is a diffusion/bf16 question, not a tokens-per-second question.

**Result type.** Mixed.

**Does not show.** The two engines differ in patch version (0.40.17 vs 0.40.16), and the desktop prefill figure could be a property of that build rather than of Ada; prefill at 3.5k context is therefore the weakest number here. Twenty MBPP tasks have a 0.05 step, so a one-task difference is noise, not a quality gap. The AWQ/Marlin and FP8 configurations the card originally asked for could not be run at all: Marlin and AWQ kernels exist only in vLLM, which has no native Windows build, and although llama.cpp defines `GGML_TYPE_F8_E4M3`, the CUDA kernels in `fp8.cu` target Ada and newer. bf16 on Volta and cuDNN-backed diffusion on the desktop were not measured.

**Raw.** `raw/runs/V100-95.json` (six JSON files: speed, long-context and MBPP runs on both machines) and `/root/runs/V100-95/run.log` on the rig.
