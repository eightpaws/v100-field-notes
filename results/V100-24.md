# V100-24 — DRY sampler and reasoning budget: a negative result

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** A widely cited llama.cpp issue (#28932) reports that the DRY repeat penalty cut the repeated-n-gram
share from 0.271 to 0.085, and the worst looping case from 41 repetitions to 2. If that reproduces, it removes the
most annoying defect of local models. Does it reproduce on this model, in Russian, at `temperature=0`?

**Environment.**

| Component | Value |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2-16GB, 16384 MiB / 580.178.04 / 7.0 (sm_70) |
| Engine | llama.cpp `llama-server` built for sm_70 |
| Model | qwen2.5-coder-14b, Q4_K (`/models/qwen2.5-coder-14b.gguf`) |
| Sampler | `--dry-penalty-last-n 1024 --dry-multiplier 0.8 --dry-base 1.75` |
| Host | Proxmox VE VM — 24 vCPU (EPYC 7282), 94 GiB RAM, Ubuntu 24.04.5, kernel 6.8.0-151 |

**Commands** (verbatim from the run script). Three modes over the same seven prompts:

```bash
# baseline
llama-server -m /models/qwen2.5-coder-14b.gguf --port 8082 -c 8192 -ngl 99 -fa on
# DRY
llama-server -m /models/qwen2.5-coder-14b.gguf --port 8082 -c 8192 -ngl 99 -fa on \
  --dry-penalty-last-n 1024 --dry-multiplier 0.8 --dry-base 1.75
# DRY + budget
llama-server -m /models/qwen2.5-coder-14b.gguf --port 8082 -c 8192 -ngl 99 -fa on \
  --dry-penalty-last-n 1024 --dry-multiplier 0.8 --dry-base 1.75 --reasoning-budget 4096
```

Prompts: five ordinary coding/list tasks plus two built to loop on purpose — 120 rose varieties numbered in
sequence, and 80 lines of synthetic log. The metric is the share of repeated 12-grams in the output, plus the worst
single repeat length.

**Results.**

| mode | repeated 12-gram share | worst repeat | decode tok/s |
|---|---|---|---|
| baseline | 0.0 | 1 | 67.14 |
| DRY | 0.0 | 1 | 65.20 |
| DRY + reasoning budget | 0.0 | 1 | 65.30 |

**Repeats.** Three modes × seven prompts, `n=1` per prompt; the table averages the prompts within a mode.

**Verdict.** The DRY penalty did not reproduce here: qwen2.5-coder-14b does not loop on Russian tasks at
`temperature=0`, so there is nothing for it to fix, and it costs about 3 % of decode speed. Keep DRY off by default
and enable it only for a specific model that actually loops. The build does accept `--reasoning-budget`, which is
the useful half of this experiment.
