# V100-27 — volta-forever: running CUDA 13 binaries on a V100

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Result type.** Mixed.

**Question.** `volta-forever` is a loader-level translator: it rewrites kernel code at program load, replacing
Turing/Ampere/Blackwell instructions with Volta equivalents. The author claims stock torch 2.14+cu130 wheels (which
carry no sm_70 PTX), vLLM and SGLang run on V100 through it, with bf16/fp8/nvfp4 emulated. Does it work on this card,
and what does the emulation cost?

**Environment.**

| Component | Value |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2-16GB, 16384 MiB / 580.178.04 / 7.0 (sm_70) |
| Layer | volta-forever 0.1.2, installed to `~/.local/share`, invoked through the `vf` prefix |
| Replacement library | libcublas 12.9.2 from the PyPI wheel `nvidia-cublas-cu12 12.9.2.10` |
| Test workload | SDXL RealVisXL V5, 1024×1024, 8 steps, cuDNN enabled, VRAM 9.5 GB |
| Host | Proxmox VE VM — 24 vCPU (EPYC 7282), 94 GiB RAM, Ubuntu 24.04.5, kernel 6.8.0-151 |

**Commands** (verbatim, in order):

```bash
# vf fetch from the NVIDIA site pulled nothing in 40 minutes; the wheel path works
pip download --no-deps nvidia-cublas-cu12==12.9.2.10

vf python -c "import torch; print(torch.__version__)"
vf python sdxl_1024_8steps.py    # cuDNN on, same seed
```

**Results.**

| Path | Frame time, s | Notes |
|---|---|---|
| volta-forever 0.1.2, cuDNN on | 41.5 | layer mapped libcublas 13 → 12.9.2, added 8846 instructions to the first fp16 conv kernel |
| Native, cuDNN off | 3.6 | same frame, same card |

**Repeats.** Single run each; the 11x gap is large enough that repetition would not change the conclusion.

**Verdict.** The layer does what it says at the compatibility level: it runs code compiled without Volta, and it is
worth keeping for exactly one situation — software released only for CUDA 13 with no sources. It is not a speed path:
emulated sm_75 instructions run on ordinary CUDA cores, so a frame that takes 3.6 s natively takes 41.5 s. Keep torch
on the native path (2.10.0+cu128 with cuDNN disabled for these pipelines) and llama.cpp on the volta-fa patches.

Side finding worth its own line: `nvidia-cublas-cu12` from PyPI is a working way to get cuBLAS when the vendor
download stalls.

**Does not show.** Does not compare against the best native path: the 3.6 s baseline runs with cuDNN disabled, because cuDNN finds no fp16 convolution engine on this stack — so 11x is emulation against the practical native fallback, not against an optimal native run. One workload (SDXL 1024×1024, 8 steps), one run per path.
