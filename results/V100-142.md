# V100-142 — VLM card controller: blind to framing

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Can a 7B vision-language model replace the heuristic quality controller for product card images? The heuristic gives numbers but no judgement and flags 93.5% of edge cases falsely. Success criterion: high recall per defect class with a low false-reject rate on clean cards.

**Environment.** Tesla V100-SXM2-16GB, cc 7.0, driver 580, CUDA 12.9 toolkit; llama.cpp 1.1.0-dev (build 1, commit `28148b5`, `/home/hermes/llama-master`) with `llama-server` and libmtmd; weights `Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf` (4.68 GB) plus `mmproj-F16.gguf` (1.35 GB) in `/srv/media/models/qwen25vl`; Python 3.12 (driver only, torch not involved).

**Commands.** `llama-server -m /srv/media/models/qwen25vl/Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf --mmproj /srv/media/models/qwen25vl/mmproj-F16.gguf -c 4096 -ngl 99 --host 127.0.0.1 --port 18331 --no-warmup`, then `POST /v1/chat/completions` with `temperature 0`, `max_tokens 64`, the image as a base64 `image_url`. The model must answer strict JSON `{"ok": true|false, "reason": "none|blurry|cropped|too_dark|color_cast|artifact"}`. Drivers: `/root/v142.py` (80 frames) and `/root/v142b.py` (48 frames, explicit border question).

**Artifacts.** [`raw/runs/V100-142.json`](../raw/runs/V100-142.json) - every frame with the model answer, token counts and latency.

**Repeats.** Single run, `temperature 0`. All 80 frames produced the same input length (1423 tokens) and 12-13 output tokens, so a repeat would return the same answer; no distribution can be quoted.

**Result.**

| Metric | Value | Unit |
|---|---|---|
| accuracy (80 frames) | 0.85 | fraction |
| recall over defects | 0.70 (28/40) | fraction |
| false rejects on clean cards | 0/40 | frames |
| blur, darkness, pixelisation | 8/8, 8/8, 8/8 | frames |
| colour cast | 4/8, correct cause named in 1 | frames |
| frame cropping | 0/8 (0/8 also with an explicit border question) | frames |
| baseline "always acceptable" | 0.50 | accuracy |
| latency per frame | 1.25 (p50), 1.21-1.34 | s |
| prompt tokens per frame | 1423 | tokens |
| VRAM | 6.7 | GB |

The test set is synthetic: 40 accepted shop cards plus five defect classes of eight frames each (Gaussian blur radius 9, a 1.7x centre zoom that pushes the product out of frame, brightness 0.38, red/blue channel cast, 14x nearest-neighbour pixelisation). Warm start of the server is 4 s with model pages in cache, 28 s cold.

**Verdict.** Usable as a filter for blur, darkness and pixelisation (24 of 24, zero false rejects), unusable as the only controller: framing crops are missed entirely, and framing is exactly where the heuristic failed.

**Result type.** Mixed.

**Does not show.** The labels are synthetic - defects were injected into accepted cards, so real production rejects were never labelled and human agreement was not measured; the border question was asked separately and still gave 0/8, so this is a property of the model rather than of the prompt; only one model and one quantisation were measured (32B, 72B and InternVL were not tried); the heuristic's 93.5% false-positive rate on edges was not re-measured, so the proposed heuristic-plus-VLM combination is not benchmarked.
