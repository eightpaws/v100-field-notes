# V100-70 — Re-rank surface search by code

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Embeddings provided the correct order for four texts, but for real search, a second step is needed: reranking of 20-50 candidates.

**Environment.** bge-reranker-v2-m3 (568M) fp16, torch from venv `/var/lib/ollama/venvs/video`; V100 16 GB (sm_70), driver 580, CUDA 12.9

**Commands.** The run script was not preserved; the runner was `/root/bin/v100-run.sh V100-NN`.

**Artifacts.** Logs were not preserved for this run.

**Repeats.** single run

**Result.** The reranker works and separates trash confidently.** bge-reranker-v2-m3 (568M, fp16) took **6.9 s** to launch on V100 and used **1092 MiB** VRAM - fits alongside working LLM, no need to unload it. On the "query - three candidates" test, scores were **2.516 / -8.930 / -5.449**: correct function was first with a 11-point lead over the next one, so threshold can be set confidently. Issues: in venv `/var/lib/ollama/venvs/video` transformers pulled `torchaudio`, which was built for CUDA 13 and failed with `libcudart.so.13: cannot open shared object file` - import broke before model loading. Fixed by `pip uninstall torchaudio` (not needed for reranker). Weights of 2.27 GB were downloaded via `dl_append.sh`: regular `curl -C -` on this file hung at 8 KB.
