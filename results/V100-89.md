# V100-89 — Colibri: Experts GPU/RAM/NVMe

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** `JustVugg/colibri` — an independent C-engine with a three-level expert placement: hot in VRAM, warm in RAM, cold streams from NVMe, plus a hardware scheduler. The only way to run a MoE frontier-sized model on a single 16 GB without vLLM-stack.

**Environment.** V100-SXM2-16GB sm_70, driver 580.178.04, CUDA 12.9, torch not participating; colibri HEAD e479104 (`/root/colibri`), engine qwen36, weights `/root/colibri-models/qwen3-coder-30b` (int4 packed), ctx 65536, python 3.12.

**Commands.** ```bash cd /root/colibri && ./c/coli serve --port 8000; measure - python3 /root/bin/v89_bench.py (3 requests, max_tokens 128, temperature 0, total request time). ```

**Artifacts.** srv/media/night/v100_89.json, logs /root/runs/v89-server.log, /root/runs/v89run.log, responses /root/runs/v89-{1,2,3}.json

**Repeats.** n=3, 5,8 / 16,2 / 16,6 tok/s (mean 12,9, stdev 5,0); first run includes heating.

**Result.** Colibri on Qwen3-Coder-30B-A3B (int4 packed, ctx 65536) yields a decode speed of **16.6 tok/s** best (5.8 / 16.2 / 16.6; average 12.9) compared to 75.5 with llama.cpp using `-ncmoe` - 4.5 times slower, criterion not met. Server startup is 440s, VRAM 8.5 GB, RSS after loading 1.8 GB, experts stream from disk (128 slots per layer). Engine built and runs on sm_70 but lags behind llama.cpp on NFS cache by a significant margin.


**Verdict.** Colibri on Qwen3-Coder-30B-A3B (int4 packed, ctx 65536) yields a decode speed of **16.6 tok/s** best (5.8 / 16.2 / 16.6; average 12.9) compared to 75.5 with llama.cpp using `-ncmoe` - 4.5 times slower, criterion not met.
