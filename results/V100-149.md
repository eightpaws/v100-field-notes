# V100-149 — The throughput of llama-server with multiple clients

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Cache prefix verified on one client and two slots; with ten simultaneous clients with different system prompts, cache may stop hitting, and the win from V100-43 will disappear. Then, the agent's contour should be built differently - one slot per role.

**Environment.** llama.cpp 1.1.0-dev, commit 28148b5, llama-server; Tesla V100 16 GB (sm_70), driver 580, CUDA 12.9; Ubuntu 24.04, 24 vCPU, 94 GB RAM; qwen2.5-7b-instruct Q4_K_M (5.1 GB), `-ngl 99 --cache-reuse 256 --metrics`

**Commands.** ```bash /root/bin/v100-run.sh V100-149 -- bash /root/v149_driver.sh Inside the driver: /home/hermes/llama-master/build/bin/llama-server -m /models/qwen2.5-7b-instruct.gguf -ngl 99 -c 8192 -np 2 --cache-reuse 256 --port 18452 --host 127.0.0.1 --metrics Harness: NP=2 CTX=8192 REPS=3 python3 /root/v149_harness.py (streaming /completion, prompt 1400 token id to client, n_predict 24, 10 threads through Barrier) ```

**Artifacts.** /root/runs/V100-149/run.log; JSON /srv/media/night/v100_149.json; server logs /srv/media/night/v100_149_srv_np1.log, _np2.log, _np4.log

**Repeats.** Warm waves n=3 (median TTFT 1130 ± 3 ms at `-np 2`, 1077 ± 27 ms at `-np 4`), cold first pass - single run; base single client n=10 requests, 491.4 ± 6.0 ms

**Result.**

**Verdict.** 10 clients with different prefixes of 1400 tokens each, response of 24 tokens, Qwen2.5-7B Q4_K_M on V100 16GB, 3 waves per configuration.

**Result type.** Mixed.

**Does not show.** one run only - repeatability was not measured; the run log was not preserved, so the numbers cannot be re-checked from this repository.

 10 clients with different prefixes of 1400 tokens each, response of 24 tokens, Qwen2.5-7B Q4_K_M on V100 16GB, 3 waves per configuration. - one client, `-np 1`: TTFT 491 ms (median of 10 requests, ±6 ms), decode 111 tok/s, VRAM 5557 MiB. - 10 clients, `-np 1`: TTFT 1565 ms (×3.19), maximum 3022 ms, total throughput 74 tok/s. - 10 clients, `-np 2` (8192): cold wave 3202 ms (×6.5), warm 1130 ms (×2.30), throughput 104 tok/s, decode per client 52 tok/s, VRAM 5781 MiB. - 10 clients, `-np 4` (16384): cold 3092 ms (×6.3), warm 1077 ms (×2.19), throughput 122-124 tok/s, decode per client 66 tok/s, VRAM 6229 MiB. - prefix cache did not collapse: on the second pass `prompt_n = 1` for all ten clients, although 10 × 1400 = 14,000 tokens do not fit into either 8192 or 16384 KV - means RAM host cache (`--cache-ram`, default 8192 MiB) works, not just KV on the card. - slots do not provide throughput: 104-124 tok/s vs 111 for one client (+7-12 %), while decode per client drops 111 → 52-66 tok/s. - context is divided into slots: with `-c 16384 -np 4` per client gets 4096 tokens, so keep `-c` equal to `np × 4096`.
