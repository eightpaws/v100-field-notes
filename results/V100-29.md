# V100-29 — PXA 4.0 engine: a 27B model on a 16 GB card

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** PXA ships pre-quantised 27B checkpoints (PXQN4, ~3.97 bits per weight) and a launcher that claims a single 16 GB card is enough. Does it run without Docker, and at what speed?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
tar -xzf pxa-v4.0.4-docker.tar.gz -C pxaimg           # OCI image, no docker needed
LD_LIBRARY_PATH=pxaimg/root/opt/pxa/dist/lib:/usr/lib/x86_64-linux-gnu \
  pxa-launch -m qwen38-27b-pxqn-onecard.gguf --engine llama -c 4096 --port 18095
```

**Results.**

| Metric | Value |
|---|---|
| Weights file | 13.6 GB, codec PXQN4, 3.97 bpw |
| VRAM after load | 14 893 MiB of 16 144 |
| prefill | 164–231 tok/s |
| decode (thinking off) | 105.7 tok/s |
| decode (thinking on) | 65–74 tok/s |
| Coding answer | correct CSV-sum function, 1.4 s |

**Repeats.** single run, three requests

**Verdict.** The first configuration that puts a 27B dense model fully on the card and still decodes faster than the 30B MoE with CPU offload. Stock llama.cpp cannot read the PXQN4 file — the PXA engine is mandatory.

**Result type.** Positive.

**Does not show.** Only one checkpoint was tested. The engine refuses to start if any VRAM is already occupied, and quality beyond a single coding prompt was not measured.
