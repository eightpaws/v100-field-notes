# V100-29 — PXA 4.0: out-of-the-box engine for Volta

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Ready tarball without build and CUDA toolkit: deploy, select card and model, press Start. Focused specifically on P100/V100/GTX-10 - cards for which tuning has stopped. Has its own quanta (PXQ/PXQN) and live leaderboard.

**Result.** PXA indeed provides 27B on a full 16 GB card. I took their v4.0.4 image (OCI tar 1.85 GB), unpacked it without Docker - the `pxa-launch` binary from `opt/pxa/dist` works if given the image's libraries (`LD_LIBRARY_PATH=<dist>/lib:/usr/lib/x86_64-linux-gnu`). The model `poisonxa/Qwen3.8-27B-PXQN-OneCard` (13.6 GB in one file, PXQN4 codec, 3.97 bits per weight). Launch: `pxa-launch -m qwen38-27b-pxqn-onecard.gguf --engine llama -c 4096 --port 18095`. | Metric | Value | |---|---| | VRAM after loading | **14,893 MiB** out of 16,144 | | prefill | 164-231 tok/s | | decode | **105.7 tok/s** (without thinking), 65-74 with thinking | | response to CSV task | working code with `csv.DictReader`, try/except, empty check, 1.4 s | For comparison: Qwen3-Coder-30B MoE requires offloading 8 expert layers to CPU and gives 75 tok/s (V100-45). Here, the 27B dense model runs entirely on GPU and is faster. Three issues: - **stock llama.cpp does not read this file** - custom PXQN4 codec, needs PXA engine; - `pxa-launch` refuses to start if anything is occupied on the card: a music studio (310 MB) was interfering, had to kill it; - by default, the model spends the entire budget on thinking: with `max_tokens=400`, content is empty, all goes into `reasoning_content`. Fixed with `chat_template_kwargs: {"enable_thinking": false}`. Conclusion: this is the first truly working "big model in 16 GB" without offloading to RAM. Suitable for code: 105 tok/s with correct response. Artifacts: `/srv/media/night/v100_29_pxa.log`, model at `/srv/media/ai-cache/downloads/qwen38-27b-pxqn-onecard.gguf`.
