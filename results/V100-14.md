# V100-14 — 24B in 16 GB: Mistral-Small-3.1-24B AWQ

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Now the ceiling is 14B Q4: 66 tok/s. 24B in AWQ W4A16 weighs ~13 GB, that is, it fits into 16 GB, and by the bandwidth the ceiling is ~65 tok/s (realistically 40–50). This is a quality step without speed loss - if 1Cat-LLM indeed keeps AWQ kernels on sm_70.

**Result.** Mistral Small 24B AWQ does not fit in 16 GB via vLLM. The model is fully downloaded (3 shards, 13.4 GB, all tensors are read), 1Cat-vLLM 1.5.4 compiled for sm_70 and has separate SM70-paths for AWQ (`VLLM_SM70_AWQ_WARMUP_MAX_M`, INT8 KV, FA2-V100 for compute 7.0) - so the engine is ready for the card. Attempts to run on an empty card: | Configuration | Result | |---|---| | len 4096, util 0.92 | EngineCore failed | | len 4096, util 0.95 | `Failed to load model - not enough GPU memory` | | len 2048, util 0.96, eager | same | | len 1024, util 0.97, eager | same | The weight part is 13.36 GiB according to vLLM itself, and with activators, CUDA graphs, and INT8-KV it does not fit into 16,144 MiB. Extra space is needed for decode transit buffers. Important context: the same "large model in 16 GB" task was resolved by the PXA engine - a 27B model in a 13.6 GB file loaded onto 14.9 GB VRAM and gave 105 tok/s (V100-29). This means the issue is not with the weights but with vLLM overhead: PXA loading is more compact. Verdict: rejected in current form. Worth repeating with a smaller model (Mistral 12B AWQ or 24B in NVFP4 - see V100-44), or when 1Cat reduces the overhead.
