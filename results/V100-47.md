# V100-47 — DeepSeek-Coder-V2-Lite 16B MoE: the fastest decode on V100

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** A 16B MoE with 2.4B active parameters weighs 9.65 GB at Q4, so it fits the card entirely. Is that enough for a coding assistant, and does flash attention help or hurt?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-bench -m deepseek-coder-v2-lite-q4_k_m.gguf -p 256 -n 64 -ngl 99 -fa 0|1 -r 2
```

**Results.**

| FA | prefill tok/s | decode tok/s |
|---|---|---|
| off | 2250 ± 139 | **183.6 ± 0.5** |
| on | 228.8 ± 11 | 1.14 ± 0.03 |

**Repeats.** n=2 per configuration, bench reports mean ± stdev

**Verdict.** Best decode measured on this card by a wide margin: 183.6 tok/s with 2250 tok/s prefill, working configuration `-ngl 99 -fa 0`. Flash attention must be off — it is 160x slower on this architecture.

**Result type.** Positive.

**Does not show.** Code quality was not benchmarked; the flash-attention collapse is recorded as a fact but its kernel-level cause was not investigated.
