# V100-156 — How many clients does 27B hold and where does TTFT fail?

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** The V100-149 measured many clients on 7B; on 27B PXQN with `-np 1` and cont-batching the ceiling for memory and TTFT is different, and without this number serving 27B cannot be planned.

**Environment.** PXA 4.0.4 (`pxa-launch` from OCI image, unpacked without docker), llama engine, checkpoint `poisonxa/Qwen3.8-27B-PXQN-OneCard` (13,566,509,376 B, codec PXQN4, 3.97 bits per weight); Tesla V100-SXM2-16GB (sm_70), driver 580.178.04, CUDA 12.9, Ubuntu 24.04.5, kernel 6.8.0-151-generic.

**Commands.** `pxa-launch -m qwen38-27b-pxqn-onecard.gguf --engine llama -c 8192 --np 1 --host 127.0.0.1 --port 18510 --no-control --yes` with `LD_LIBRARY_PATH=<dist>/lib:/usr/lib/x86_64-linux-gnu`; harness `python3 /root/v156_harness.py`, reasoning disabled (`enable_thinking: false`).

**Result.** One PXA slot handles approximately 100 tok/s of aggregate at any number of clients, so only the queue grows. TTFT (median by repeats, each client requests 128 tokens): 1 client - 297 ms (p95 307), 2 clients - 840 ms (p95 2257), 4 clients - 2311 ms (p95 5203), 8 clients - 5317 ms (p95 11079). Aggregate: 90.9 / 105.5 / 100.8 / 100.6 tok/s respectively. Peak VRAM 14931 MiB, rise 40s. Saturation point - two clients: p95 TTFT threshold of 2s is already reached on the second one.
