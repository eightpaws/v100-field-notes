# V100-50 — Speculative decoding for code

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** The code is predictable: a draft model of 0.5-1.5B should give 1.5-2.5x on 14B. In the queue is V100-01 on speculation in general, here - targeted at the code and with measuring the share of accepted drafts.

**Result.** Speculative decoding on our card works and gives around +20% on the code. Tested on llama-server master 51831d4 (CUDA 12.9): target Qwen2.5-Coder-7B-Instruct Q4_K_M, draft Qwen2.5-0.5B-Instruct Q8 (645 MB), flags `--spec-type draft-simple -md <draft> --spec-draft-ngl 99 --spec-draft-n-max 8`, context 4096, one slot. | Mode | Decode, tok/s (three runs) | --- | --- | Without draft | 111.5 / 114.2 | | **With draft** | **134.6 / 140.3 / 136.4** | Average gain 21%. Prompt is the same: "write a function that reads CSV and sums up column amount", 96 tokens of response. Time-consuming pitfalls: - in this build speculative type is called `draft-simple`, not `draft`; old `--draft-max` renamed to `--spec-draft-n-max`; - **`llama-cli` does not include speculation at all** - flag `-md` is accepted silently, but token count does not change (112.8 vs 112.9). Works only through `llama-server` with explicit `--spec-type`; - without `--spec-draft-ngl 99` draft stays on CPU and there is no gain; - quantized KV (`-ctk q8_0`) with `-fa 0` does not load: compressed KV requires enabled FA.
