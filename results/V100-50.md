# V100-50 — Speculative decoding for code generation

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Does a 0.5B draft model accelerate coding output from a 7B target on V100, and how should the server be configured?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-server -m qwen2.5-coder-7b-instruct-q4_k_m.gguf -md qwen2.5-0.5b-instruct-q8_0.gguf \
  --spec-type draft-simple --spec-draft-ngl 99 --spec-draft-n-max 8 -ngl 99 -fa 0 -c 4096
```

**Results.**

| Mode | decode tok/s (three runs) |
|---|---|
| without draft | 111.5 / 114.2 |
| with draft | **134.6 / 140.3 / 136.4** |

**Repeats.** n=3 with draft, n=2 without, identical prompt and 96 output tokens

**Verdict.** +21% on a 7B target. The same draft on a 14B target slows decoding by 43% — the technique has to be measured per pair, not assumed.

**Result type.** Positive.

**Does not show.** No acceptance-rate instrumentation; the gain is explained by the target/draft size ratio, not measured per token.
