# V100-148 — PXA: Second checkpoint and quality 27B

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** 105.7 tok/s at one checkpoint PXQN does not indicate the class of models: a second checkpoint of the same quantum is needed along with a quality measurement, otherwise it is unknown whether we are paying for speed at the expense of degradation.

**Environment.** PXA 4.0.4 (`pxa-launch` from OCI image, unpacked without docker), llama engine, V100-SXM2-16GB sm_70, driver 580.178.04, CUDA 12.9; checkpoint `poisonxa/Qwen3.8-27B-PXQN-OneCard` (13,566,509,376 B) and `poisonxa/Swift-1.5-Qwen3.8-27B-PXQN-OneCard` (13,566,508,256 B), same codec PXQN4; guest VM on local stand, Ubuntu 24.04, kernel 6.8.0-151

**Commands.** ```bash /root/bin/v100-run.sh V100-148 -- bash /root/v148_driver.sh ; inside, for each checkpoint LD_LIBRARY_PATH=<dist>/lib:/usr/lib/x86_64-linux-gnu pxa-launch -m <file> --engine llama -c 4096 --port 18095 --no-tui --no-interactive --yes then python3 /root/code_eval.py --base-url http://127.0.0.1:18095 --model <model id from /v1/models> --tasks 40 --no-think --max-tokens 1536 --out /srv/media/night/v100_148_<tag>.json ; run decode separately with v100-run.sh V100-148b and /root/v148_speed2.py <port> <tag> 256 ```

**Repeats.** Quality - n=2 at checkpoint (40 tasks, 1 task = 2.5 pp.): Re-running with Harness using the same flags resulted in the same 24/40 and 25/40, both immediately matched 40/40; Decode - n=3, range of warm calls 162.1-163.0 tok/s, first call not included in average

**Result.** Second checkpoint PXQN yielded the same quality: MBPP pass@1 **0.625 (25/40)** compared to **0.60 (24/40)** at V100-29 checkpoint, indicating a difference of one task - noise from a single run, not degradation. Warm decode for both was **162 tok/s** (server `timings.predicted_ms`), first cold call was 106 tok/s: previous 105.7 tok/s in V100-29 were taken on the first call. Both models are entirely on the card, peak 14,583 MiB. Base line - Qwen3-Coder-30B-A3B with CPU offloading of 8 expert layers: 0.60 pass@1 and 75 tok/s (V100-66). Dense 27B in 4-bit PXQN provides the same quality and speed, but without offload: 30B MoE is limited by 16 GB, this one is not.

**Does not show.** Only Python and MBPP on 40 tasks; a set of 200 tasks and other languages were not pursued, so the difference of one task cannot be interpreted as "second checkpoint better"; reasoning was disabled via `chat_template_kwargs`, behavior with it enabled was not measured; comparison with 30B MoE is field (different engine and different harness run).
