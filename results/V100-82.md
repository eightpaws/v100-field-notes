# V100-82 — 262K context on a single 16 GB card

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 96 GiB RAM, driver 580.178.04._

**Question.** Does llama.cpp hold a 262 144-token context window on one 16 GB Volta card, and what does it cost in memory and prefill speed?

**Environment.**

| Component | Value |
|---|---|
| Build | llama.cpp af5c583 (`build129`), CUDA 12.9.41, sm_70 |
| Model | Qwen2.5-0.5B-Instruct Q8_0 |
| Server | `llama-server -ngl 99 -fa on`, prompt of 12 000 tokens |

**Measurements.** Card confirmed empty before each start; a fresh server per row.

| Context | KV cache | VRAM at load | Prefill | Prompt tokens |
|---|---|---|---|---|
| 65 536 | q8_0 | 1 379 MiB | 9 619.7 tok/s | 12 000 |
| 131 072 | q4_0 | 1 499 MiB | 10 381.3 tok/s | 12 000 |
| **262 144** | **q4_0** | **2 123 MiB** | **10 300.5 tok/s** | 12 000 |

All three configurations start and serve. Prefill speed barely depends on the declared ceiling (9.6–10.4 k tok/s) because the KV cache is allocated lazily and q4_0 is cheap at this model size. At 262k the server holds only 2.1 GB, leaving room for roughly 15 GB of weights.

**Verdict.** Yes for a small model: 262k fits on 16 GB with quantised KV. The ceiling is set by model size, not by the card: 0.5–1B reaches 262k, a dense 7B is realistic at 64k, and a 30B MoE at 8–16k.

**Result type.** Positive, with a scope limit.

**Does not show.** Only one small model was tested. KV memory grows with layer count and head count, so these numbers do not transfer to 7B or 30B models — for those the same table was measured separately (V100-56: 7B at 32k q8_0 and 64k q4_0; V100-51: 30B MoE at 32k).
