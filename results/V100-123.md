# V100-123 - Quant ladder for a 30B MoE code model: Q4, Q5, Q6, Q8

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Environment.** llama.cpp build 12359 (commit b1b770d90), CUDA toolkit 12.9, driver 580, one V100 16 GB, ctx 8192 with 4 slots, harness `/root/code_eval.py`, MBPP set of 40 tasks, temperature 0.

**Commands.**

```
llama-server -m Qwen3-Coder-30B-A3B-Instruct-<QUANT>.gguf -ngl 99 -ncmoe <N> -c 8192 \
  --host 127.0.0.1 --port <PORT> -t 8 -a qwen3coder30b-<QUANT>

python3 /root/code_eval.py --base-url http://127.0.0.1:<PORT> \
  --model qwen3coder30b-<QUANT> --tasks 40 --no-think --out /srv/media/night/v100_123_<QUANT>.json
```

`-ncmoe` per quant: 16 (Q4_K_M), 24 (Q5_K_M), 32 (Q6_K), 40 (Q8_0). Without expert offload the 32.5 GB Q8 file does not fit in 16 GB of VRAM.

**Results.** MBPP pass@1, 40 tasks, single run per quant:

| Quant | File size | -ncmoe | pass@1 | Correct | s / task | tok/s | VRAM after load |
|---|---|---|---|---|---|---|---|
| Q4_K_M | 18.6 GB | 16 | 0.525 | 21 / 40 | 2.32 | not recorded | not recorded |
| Q5_K_M | 21.7 GB | 24 | 0.550 | 22 / 40 | 2.73 | 30.6 | 12.0 GB |
| Q6_K | 25.1 GB | 32 | 0.550 | 22 / 40 | 3.60 | 23.1 | 9.9 GB |
| Q8_0 | 32.5 GB | 40 | 0.525 | 21 / 40 | 4.98 | 17.1 | 7.6 GB |

Quality plateaus at Q5_K_M. Q6_K and Q8_0 solve no additional task, and the 21-22 out of 40 spread is inside the noise of a 40-task set. The cost of the higher quants is real: Q8_0 takes 1.8x the time per task of Q5_K_M (4.98 vs 2.73 s) and produces 1.8x fewer tokens per second (17.1 vs 30.6), needs 40 expert layers pushed to RAM, and occupies 11 GB more disk. For code on a single 16 GB V100 the ceiling is Q5_K_M.

**Repeats.** Single run per quant (40 tasks, temperature 0, greedy). Speed figures are the mean of the same run, not a repeat series, so differences under about 5 percent should be read as noise.

**Verdict.** Negative for Q6 and Q8: no quality gain over Q5_K_M, only more time, RAM and disk. Q5_K_M is the recommended quant for a 30B-A3B code model on one 16 GB Volta card.

**Result type.** Negative.

**Does not show.** Q4_K_M VRAM was not recorded, so the four quants are not fully comparable on memory. Only the 40-task MBPP subset was run: with n=40 a single task is 2.5 percentage points, so Q4/Q8 at 21 and Q5/Q6 at 22 are statistically indistinguishable. The second arm of the plan - 10 diff-review tasks - was measured only for Q4 (see card V100-123 in the queue), not for Q5-Q8. All runs used one client against four server slots, so the tok/s numbers are single-stream, not saturated batching.
