# V100-75 — GLM-4.7-Flash-30B-A3B IQ4_XS: fresh 30B MoE

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Qwen3-Coder-30B-A3B produced 75 tokens/s at -ncmoe 8. GLM-4.7-Flash of the same class but newer; IQ4_XS weighs 16.71 GB - 0.5 GB less than Qwen, so it can fit with fewer layers on CPU.

**Result.** Speed is good, model is degenerative.** Architecture is `deepseek2` (like DeepSeek-Coder-V2), so FA is off. Matrix `-ncmoe` (IQ4_XS 15.56 GB, 31.22B): ncmoe 8 - prefill **727.5** tok/s, decode **59.5**; ncmoe 12 - 539.0 / 55.4; ncmoe 16 - 445.8 / 52.9. For comparison, Qwen3-Coder-30B-A3B on ncmoe 8 gives 411.9 / 75.5: GLM is faster on prefill and slower on decode. **But quality is zero due to assembly, not architecture.** Harness gave code 0/40, format 1/5, RAG 0/2, content 0 words at 1400 generated tokens, tools 0 calls. Checking response structure explained: model writes infinite `GGGGGGGG...` in `reasoning_content` field and never reaches `content` - at limit 200 and at 800 tokens same, `finish_reason=length`. This is a defect of specific DavidAU (Hellfire-Turbo-Brilliance-50x-AGI-NEO) build, not all GLM-4.7. Official checkpoint was not tested: 18 GB channel spent on this build overnight. Conclusion: speed and capacity class has, but official weights should be taken.
