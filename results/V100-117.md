# V100-117 — Cost of a typical order: machine hours and price for six types of work

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** If code for a typical freelance order is written by a local 7B model, what does one order actually cost in machine time and tokens - and is the machine the expensive part, or the human review around it?

**Environment.** Tesla V100-SXM2-16GB (sm_70, 900 GB/s), driver 580.178.04, power limit 300 W (the card runs at its cap during decode); llama.cpp build129 (`/home/hermes/llama-new/build129`), Qwen2.5-Coder-7B-Instruct Q8_0 (8.1 GB), `-ngl 99 -c 8192 --jinja`, temperature 0.0, greedy; guest VM on a home stand: 24 vCPU, 94 GiB RAM, Python 3.12.3, PHP 8.3.

**Commands.**

```
/root/bin/v100-run.sh V100-117 -- /root/venvs/app/bin/python /root/proj117.py
```

The driver starts one `llama-server` for the whole batch, then for each order type: asks for a file plan (JSON), generates every file with the spec plus already written files as context, runs the acceptance check, and on failure performs up to two repair rounds (same spec plus the acceptance output, implementation file only).

**Results.** Six order types, acceptance tests shipped with the task (the model could not edit them), one model load for the batch:

| Order type | First version, s | Total, s | Repair rounds | Acceptance |
|---|---|---|---|---|
| Telegram bot (order intake, no third-party libs) | 10.3 | 10.7 | 0 | passed |
| WooCommerce hook (pickup discount, PHP 8.2) | 6.8 | 6.9 | 0 | passed (`php -l` plus 5 code checks) |
| API client with retries (httpx) | 21.6 | 22.9 | 0 | passed |
| Landing page (HTML/CSS, no CDN) | 22.6 | 22.6 | 0 | 9 of 10 checks (catalog without prices) |
| Price parser (stdlib `html.parser`) | 31.1 | 42.6 | 2 | failed: `int('1290 rub')` on the currency word |
| File organizer (stdlib, collisions) | 27.7 | 37.0 | 2 | failed: `organize()` moves nothing |

Totals: **142.7 s** of wall clock for all six, 20,489 prompt and 11,334 completion tokens (79 tok/s effective, single stream). At the 300 W cap that is 0.0119 kWh, about **0.07 RUB** for the whole batch at 6 RUB/kWh; extrapolated, **1M output tokens costs about 6.3 RUB** of electricity. Model-generated code never exceeded 62 lines per file.

**Repeats.** Single run (n=1): six types in one batch, one cold model load, up to two repair rounds per type. No repeats, so no stdev - the spread between types is far larger than the noise would be.

**Verdict.** The machine is not the cost. Six orders cost seven kopecks of electricity and under three minutes of GPU time; two of six needed the full two repair rounds and still failed, which is where the hours go. Price an order by human review and debugging time, not by tokens: a 7B Q8 model passes three of six acceptance suites on the first attempt, matches one more on nine of ten checks, and loses two to defects a reviewer has to find and fix.

**Result type.** Mixed.

**Does not show.** Human hours: review, debugging and final polish were not timed, and neither was collecting real specs from freelance boards - the six specs were written for this run, not taken from live listings. Prices in roubles are not measured at all: the card gives machine cost only, plus the finding that human time dominates. One run per type, so the failure set is a sample, not a rate. Acceptance tests were authored by the harness from the same spec, which is stricter than "the model tests itself" but still not a client's suite.
