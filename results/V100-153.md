# V100-153 — Reasoning budget on 27B: what thinking buys

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** With reasoning switched off the same 27B checkpoint scored 0.600 on 40 MBPP tasks. Does a bounded reasoning budget buy any task, and what does it cost in time? The card was written to settle whether thinking should be on by default for code tasks of MBPP size.

**Environment.** PXA 4.0.4, `pxa-launch --engine llama` (llama-server inside, flags `-ngl 999 -sm layer -c 4096 -np 1 -fa on --cont-batching --jinja`); quant poisonxa/Qwen3.8-27B-PXQN-OneCard, 13,566,509,376 B = 3.969 BPW, fully resident; Tesla V100 16 GB (sm_70), driver 580, CUDA 12.9; Ubuntu 24.04, 24 vCPU, 94 GiB RAM. VRAM peak 14,643 MiB, server startup 5 s.

**Commands.** `bash /root/bin/v100-run.sh V100-153 -- bash /root/v153_driver.sh`; inside, one short-lived server per mode:
`pxa-launch -m qwen38-27b-pxqn-onecard.gguf --engine llama -c 4096 --port 18102 --reasoning-budget 512 --no-tui --no-interactive --yes`
then `python3 /root/v153_eval.py --base-url http://127.0.0.1:18102 --model <id> --tasks 40 --think-budget 512 --max-tokens 1536 --out /srv/media/night/v100_153_t512.json`.
Mode off: `--no-think`, no server flag, max_tokens 1536. Mode 2048: `--reasoning-budget 2048`, max_tokens 3072.

**Results.**

| Mode | pass@1 | Tasks | Time per task, s | Total, s | Tokens | Reasoning |
|---|---|---|---|---|---|---|
| No reasoning | 0.600 | 24/40 | 1.55 | 61.8 | 4,865 | No |
| Budget 512 | 0.600 | 24/40 | 5.88 | 235.1 | 18,208 | Yes, 40/40 |
| Budget 2048 | 0.600 | 24/40 | 11.72 | 468.8 | 37,604 | Yes, 40/40 |
| Score gain | 0 tasks | | | | | |
| Cost | 3.8x | 7.6x | | | | |

**Result.** MBPP pass@1 is **0.600 (24/40)** in all three modes, so reasoning bought no task at either budget. The cost is 5.88 s per task at budget 512 (3.8x the 1.55 s of no reasoning) and 11.72 s at budget 2048 (7.6x), paid for zero score change. The passing set is not the same, though: tasks 9 and 20 are gained and tasks 4 and 36 are lost, so the equal totals are two wins against two losses rather than identical answers. Budgets 512 and 2048 produced the same passing set and the same reasoning median of 488 tokens: the model stops on its own well below either cap, so anything above 512 tokens is unusable spend.

**Verdict.** Thinking does not pay on MBPP-sized tasks: the score is unchanged and the run costs 3.8x to 7.6x more wall time, so it stays off by default.

**Result type.** Negative.

**Does not show.** One run per mode, so the run-to-run spread is unknown, and the 2-gained/2-lost task swap is within what a single run cannot separate from noise. Only one checkpoint and one engine were measured. The engine ignores a request-level `thinking_budget` field and honours only the server flag `--reasoning-budget`, which cost one discarded series before the flag was found.

**Raw.** `raw/runs/V100-153.json` — per-mode totals and per-task pass/fail flags; the full server logs stay on the rig at `/root/runs/V100-153/run.log` and `/srv/media/night/v100_153_{off,t512,t2048}.json`.

**Repeats.** Single run per mode, 40 MBPP tasks, temperature 0 in the request. Modes 512 and 2048 returned the same passing set, so no spread between them was computed.
