# V100-153 — Budget for 27B: what it provides

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** With `--no-think` 27B PXQN achieved 0.600 on 40 tasks; with thinking, quality may improve and time may triple; need response if budget for reasoning on tasks of MBPP size is justified.

**Environment.** PXA 4.0.4, pxa-launch --engine llama (within llama-server with -ngl 999 -sm layer -c 4096 -np 1 -fa on --cont-batching --jinja); quantum poisonxa/Qwen3.8-27B-PXQN-OneCard 13,566,509,376 B (3,969 BPW) entirely on card; Tesla V100 16 GB (sm_70), driver 580, CUDA 12.9; Ubuntu 24.04, 24 vCPU, 94 GB RAM. VRAM peak 14,643 MiB, server startup 5s.

**Commands.** bash /root/bin/v100-run.sh V100-153 -- bash /root/v153_driver.sh; inside, each mode has its own server: /srv/media/ai-cache/downloads/pxaimg/root/opt/pxa/dist/pxa-launch -m /srv/media/ai-cache/downloads/qwen38-27b-pxqn-onecard.gguf --engine llama -c 4096 --port 18102 --reasoning-budget 512 --no-tui --no-interactive --yes, then python3 /root/v153_eval.py --base-url http://127.0.0.1:18102 --model <id> --tasks 40 --think-budget 512 --max-tokens 1536 --out /srv/media/night/v100_153_t512.json. Mode off: --no-think, no server flag, max_tokens 1536; mode t2048: --reasoning-budget 2048, max_tokens 3072.

**Verdict.** Thinking does not provide any task beyond: MBPP pass@1 **0.600 (24/40)** in all three modes.

**Result type.** Mixed.

**Does not show.** one run only - repeatability was not measured; the run log was not preserved, so the numbers cannot be re-checked from this repository; no second engine or model was measured on the same harness.

**Raw.** Not preserved for this run.

**Artifacts.** /root/runs/V100-153/run.log; /srv/media/night/v100_153_off.json, v100_153_t512.json, v100_153_t2048.json (40 lines each with task, time, tokens, and finish_reason for the mode); server logs /tmp/v153_off.log, /tmp/v153_t512.log, /tmp/v153_t2048.log.

**Repeats.** Single run on mode, 40 tasks MBPP, temperature 0 in request; modes 512 and 2048 matched set of completed tasks, therefore spread between them was not measured.

**Result.** Thinking does not provide any task beyond: MBPP pass@1 **0.600 (24/40)** in all three modes. Budget 512 takes **5.88 s** per task compared to 1.55 without thinking (3.8 times), budget 2048 - **11.72 s** (7.6 times), and the count is the same. The set of passed tasks has shifted: tasks 9 and 20 won, 4 and 36 lost, so the tie in score does not mean matching answers. Budgets 512 and 2048 produced the same task set and the same median thinking of 488 tokens: the model stops itself earlier than any ceiling, so a budget above 512 is not cost-effective. Verdict: on MBPP-sized tasks, thinking should not be enabled by default.
