# V100-99 — Prompt-expander: LLM writes prompt for photographer

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** In the disassembled workflow, the prompt for an image is written not by a human, but by a LLM: it takes two words ("face cream") as input and produces a detailed description with pose, lighting, background, and a negative prompt from ready-made defaults. This, rather than the model, is what makes the difference in quality. Our prompts are handwritten and therefore lack richness.

**Environment.** Tesla V100-SXM2-16GB (cc 7.0, 16 * 144 MiB), driver 580.178.04, CUDA 12.9.41 in `/home/hermes/cuda-12.9`, Ubuntu 24.04, EPYC 7282 (24 vCPU), 94 GiB RAM; LLM - Ollama 0.40.16, model vikhr-nemo-12b (7.5 GB, Q4); images - diffusers 0.39.0 + torch 2.10.0+cu128 (`/var/lib/ollama/venvs/video`), `torch.backends.cudnn.enabled = False`, `enable_model_cpu_offload()`.

**Repeats.** Single run to each position in every series (n=1); Spot-check at 5 positions, one side per position. LLM time range in series 2: 0.93-1.13 s on warmed-up model, 4.39 s on the first (cannot include it in average).

**Result.** The hypothesis was partially confirmed, and the solution depends on the prompt length. 20 product positions via vikhr-nemo-12b: valid JSON 20/20, all three keys 20/20, English without Cyrillic 20/20, 2.52 seconds per position on average (first 16.5s - cold load), 98-131 output tokens (was 124-189 in prototype). Visual spot-check on 5 positions (RealVisXL V5, 832x1216, 30 steps): long prompt 27-36 words gave 3/5 for material and color (vase and eustoma disappeared, pot lost packaging), short prompt in fixed order (16-22 words, 53-67 tokens) - 5/5. Packaging-box in frame 1 out of 5: SDXL draws the product, not the packaging, and ask for box separately.
