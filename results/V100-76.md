# V100-76 — Ternary-Bonsai-2-27B: 27B in 6 GB on ternary scales

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** PTQ1_0 ternary weights yield 27B in 5.95 GB - half the size of 27B in Q4 (13.6 GB for PXA). If cores run on Volta, we get a larger model without layer eviction in RAM.

**Result.** Blocked by format (24.11).** File is valid (GGUF v3, 851 tensor, 5,946,648,928 bytes), but weights are compressed with type `PTQ1_0`, which llama.cpp does not support: the engine knows `TQ1_0` and `TQ2_0`, not the `P`-variant, and fails with `failed to read tensor info`. Needs fork of prism or conversion to TQ1_0/Q2_K. Still in queue.
