# V100-76 - Ternary-Bonsai-2-27B: a 27B model in 5.95 GB, engine decides

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 24 vCPU, 94 GiB RAM._

**Question.** Ternary weights (PTQ1_0, 1.75 bpw) put a 27B model into 5.95 GB against 13.6 GB at Q4. Do the
ternary kernels execute on Volta, and is the result good enough for code work?

**Environment.** V100-SXM2-16GB (sm_70). File `Ternary-Bonsai-2-27B-PTQ1_0.gguf`, 5 946 648 928 bytes,
26.90 B parameters, group 128. Two engines were tried:

| Engine | Result |
|---|---|
| `llama-prism`, build `f702476` (PrismML runtime) | runs |
| `xyznq1/xyz-llama`, HEAD `f095f4d`, built for sm_70 | aborts on the first matmul |

**Commands.**
```
# working engine
llama-bench -m Ternary-Bonsai-2-27B-PTQ1_0.gguf -p 256 -n 64 -r 3
llama-server -m <file> -ngl 99 -c 8192 --host 127.0.0.1 --port 18495 -t 8 --jinja
python3 /root/code_eval.py --base-url http://127.0.0.1:18495 --model bonsai --tasks 40 --max-tokens 700 --no-think

# failing engine
llama-bench -m <file> -ngl 99 -p 32 -n 8 -r 1
```

**Repeats.** `llama-bench -r 3` for prefill and decode; MBPP is a single run of 40 tasks.

**Result.** On the PrismML runtime the ternary path works: prefill **815.88 +/- 11.60 tok/s** at pp256,
decode **67.13 +/- 0.08 tok/s** at tg64, server at **7 041 MiB**, and **MBPP pass@1 0.55 (22/40)** at 50.1
tok/s and 1.82 s per task. Forced onto the CPU the same file decodes at 0.47 tok/s, so the GPU path is
real and not a silent fallback.

The xyz-llama fork refuses the model outright:
`ggml-cuda/mmvq.cu:1273: PTQ1_0 ILV16: no tensor-core path for this call (ids=0, ncols=1, cc=700)`.

**Verdict.** Positive, with a correction. This card was closed once on the xyz-llama abort and claimed
ternary weights refuse to run on Volta - that was wrong, and the mistake was generalising from one fork to
the architecture. The PrismML build runs the same file at 67 tok/s and 0.55 pass@1, which clears both bars
(40 tok/s and 0.5). A 27B in 6 GB is usable on this card today; the engine matters more than the hardware
claim suggests.

**Result type.** Unstated - the result reports measurements without an explicit pass/fail verdict.

**Does not show.** No comparison against the same model at Q4 on this card, so what the 1.75 bpw ternary
format costs in quality is unknown. Long-context behaviour (the card asked for 8k onwards) was exercised
only at 8k for the server, and the fork's abort was not root-caused beyond the kernel message.

**Raw.** `raw/runs/V100-76.json` - both engines, both numbers, quality run, and the note on the earlier
wrong closing.
