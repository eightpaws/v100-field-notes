# V100-76 - Ternary-Bonsai 2 27B: ternary weights on Volta

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 24 vCPU, 94 GiB RAM._

**Question.** Ternary (PTQ1_0, 1.75 bpw) puts a 27B model into 5.95 GiB, three times smaller than the
same model at Q4. If the ternary kernels actually execute on Volta, the card gets a much larger model
without running out of memory. Does it?

**Environment.** V100-SXM2-16GB (sm_70), CUDA 12.9. The file is
`Ternary-Bonsai-2-27B-PTQ1_0.gguf`, 5 946 648 928 bytes, 26.90 B parameters. Plain upstream llama.cpp
cannot even open it: `failed to read tensor info`, because tensor type 143 is not a known
`GGMLQuantizationType`. The model's own runtime is the fork `xyznq1/xyz-llama` (HEAD `f095f4d`), built
here with `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70`.

**Commands.**
```
git clone --depth 1 https://github.com/xyznq1/xyz-llama /root/xyz-llama
cmake -S /root/xyz-llama -B /root/xyz-llama/build -DGGML_CUDA=ON \
      -DCMAKE_CUDA_ARCHITECTURES=70 -DLLAMA_CURL=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build /root/xyz-llama/build -j 20 --target llama-bench llama-server
./build/bin/llama-bench -m Ternary-Bonsai-2-27B-PTQ1_0.gguf -ngl 99 -p 32 -n 8 -r 1
./build/bin/llama-bench -m Ternary-Bonsai-2-27B-PTQ1_0.gguf -ngl 0  -p 64 -n 16 -r 1
```

**Repeats.** One run per configuration - both configurations gave a categorical answer, not a spread.

**Result.** On the GPU the fork aborts immediately with
`ggml-cuda/mmvq.cu:1273: PTQ1_0 ILV16: no tensor-core path for this call (ids=0, ncols=1, cc=700)`:
the ternary matrix-vector kernel exists only as a tensor-core path, and the V100's compute capability
(7.0) has no matching one. Forced onto the CPU the same file loads and reports
`qwen35 27B unknown, may not work`: prefill 29.06 tok/s, **decode 0.47 tok/s**.

**Verdict.** Negative and final for this card: ternary weights do not execute on Volta at all - the
kernel refuses by design rather than falling back silently, and the CPU path is 85 times below the
40 tok/s bar. A 27B in 6 GiB is a real thing, but not on this card; the same 6 GiB on a 40-series card
is where that idea belongs.

**Result type.** Negative.

**Does not show.** Quality: with no working execution path there was nothing to score. Whether the
abort is specific to the `ILV16` layout or to all PTQ1_0 shapes on sm_70 was not separated, and the
fork's speculative drafter was not exercised at all.

**Raw.** `raw/runs/V100-76.json` - the abort message, CPU numbers, and the upstream loader error.
