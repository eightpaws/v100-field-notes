# V100-144 — Inkling 2 Mini: looped MoE, depth without weight growth

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Inkling-2-Mini (26.4B total, 3.4B active; layers 6-17 form a loop core that is run several times) exposes a `reasoning_effort` knob in its chat template: same weights, a different number of passes through the core. What does one extra loop cost on a V100 — in decode speed and in MBPP quality?

**Environment.**

| Item | Value |
|---|---|
| GPU | Tesla V100-SXM2-16GB, sm_70, driver 580.178.04 |
| Engine | llama.cpp master build129 (binary 24.11.2026), CUDA 12.9 |
| Model | Inkling-2-Mini-UD-Q3_K_XL, 13,631,779,296 B |
| Launch flags | `-ngl 99 -c 8192 --jinja -t 8` |
| Host | Ubuntu 24.04, 24 vCPU, 94 GiB RAM (Proxmox VM) |
| VRAM after load | 15,033 MiB at 8192 context |

**Commands.**

```
/root/bin/v100-run.sh V100-144 -- bash /root/bin/v144_run2.sh

llama-server -m /srv/media/models/inkling/Inkling-2-Mini-UD-Q3_K_XL.gguf \
  -ngl 99 -c 8192 --jinja -t 8 --host 127.0.0.1 --port 18415

# per request
{"chat_template_kwargs": {"reasoning_effort": "none | medium | high"}}

# quality harness, 12 MBPP tasks per level
python3 /root/code_eval_eff.py --base-url http://127.0.0.1:18415 --model inkling \
  --tasks 12 --max-tokens 1536 --effort <level>
```

**Results.**

| reasoning_effort | MBPP pass@1 | passed | tokens/answer | s/task | decode tok/s (n=3) |
|---|---|---|---|---|---|
| none | 0.583 | 7/12 | 625 | 18.3 | 32.99 ± 1.89 |
| medium | 0.750 | 9/12 | 622 | 18.2 | 33.25 ± 1.46 |
| high | 0.583 | 7/12 | 939 | 27.5 | 33.26 ± 1.49 |

**Repeats.** Decode: three 96-token generations per level, mean ± stdev. Quality: single run of 12 tasks per level.

**Verdict.** Mixed — the knob moves the token budget, not the speed: decode sits at 33 tok/s on all three levels, while `high` spends 51% more tokens per answer and is not better than `medium` (7/12 against 9/12). Loop depth is not a free quality dial on this card.

**Result type.** Mixed.

**Does not show.** Only 12 of 40 MBPP tasks — the full set runs ~44 s per task (~29 min per level) and did not fit the queue tick, so the two-task gap between `medium` and `none` is inside the noise of a 12-task sample, and the `high` result is not significantly worse than `medium`. One model, one quant (Q3_K_XL); Q2_K_XL was not compared, 8k-context quality was not tested, and it was not established whether `reasoning_effort` changes the number of loop passes or only shapes the prompt.
