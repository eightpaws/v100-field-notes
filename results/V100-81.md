# V100-81 — MOE cache experts in RAM instead of `-ncmoe`

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** In llama.cpp, `moe_cache_size` and `moe_cache_cpu_share` (#30966) have been added: some experts live in RAM, hot ones are cached in VRAM, a miss does not block the stream. Authors' benchmark: A 36.3 GB VRAM MoE model ran at 72% speed of a fully resident one. Our `-ncmoe` evicts experts statically and pays for it with prefill.

**Environment.** Tesla V100-SXM2-16GB (cc 7.0) · Driver 580.178.04 · Builds `51831d4` (`/root/llama-old`) and `v1.0.0 = b1b770d` (`/root/llama.cpp`), both via `~/bin/build-cuda.sh` with CUDA 12.9.41 (`/home/hermes/cuda-12.9`), host compiler gcc-12 · Ubuntu 24.04, EPYC 7282 (24 vCPU), RAM 108 GB.

**Commands.** `/root/{llama-old,llama.cpp}/build/bin/llama-cli -m /srv/media/ai-cache/downloads/qwen3-coder-30b-a3b-q4_k_m.gguf -ngl 99 -ncmoe <8|12> -c <4096|8192> -fa off -t 8 -p "<prompt>" -n <32|8> --ignore-eos --no-display-prompt --temp 0 --single-turn [--moe-cache-mib 1024]`. (Russian note in the field notes is omitted from this English export.)

**Artifacts.** /srv/media/night/v100_81.json; /srv/media/night/v100_81b.json; /root/runs/V100-81/run.log. (Russian note in the field notes is omitted from this English export.)

**Repeats.** tg32 n=3 on configuration (72,1 ± 1,0 · 58,8 ± 0,1 · 72,5 ± 0,6 · 58,5 ± 2,6 · 59,0 ± 0,5); prefill one pass per point; 8k - single run. Prompts ~128/2048/8000 tokens (94/1517/5925 words: exact token count not taken).

**Result.** Experts cache on sm_70 is not profitable: it doesn't fit on the card with `-ncmoe 8`, and when it fits (with `-ncmoe 12`), it loses to the current scheme. At `-ncmoe 12`, cache indeed returns prefill (on working build 1069 vs 985 on pp2048, +8.5%; on v1.0.0 661 vs 631, +4.7%) and doesn't help decoding (56.1 vs 57.8). Conclusion based on the criterion: 75.5 tok/s at ncmoe 8 is not reached, 8k cache doesn't save (see below), so we stay with `-ncmoe 8` without cache. Side effect confirms regression of v1.0.0 on MoE: pp2048 1191 → 701 (-41%), decode remains the same. **8k.** `-c 8192 -ncmoe 12` works on both builds (51831d4: 983.5 prefill / 47.8 decode; v1.0.0: 638.9 / 44.7). With cache 1024 on 8k, both engines fail `CUDA error` at peak 16.1 GiB: cache takes memory from KV, not adding it.
