# V100-61 - GQA to MHA expansion: nothing in the pipeline can carry it

**Question.** The kernel-level measurement (V100-19) found the GQA-to-MHA K/V expansion running 7.2x faster than the generic math path on one shape. Does that gain survive in a real pipeline, where attention is only part of the frame time?

**Environment.** Tesla V100-SXM2 16 GB, sm_70, driver 580.178.04, CUDA 12.9, Ubuntu 24.04, guest on a Proxmox VE host. No run was made: this card is an inventory check, and the environment line describes the rig that was inspected.

## Result

No pipeline on this rig can host the expansion, and that is the result:

| Family on disk | Attention | Can host the GQA to MHA expansion? |
|---|---|---|
| SDXL, Flux.1-schnell, SD3.5-large | MHA | no - nothing to expand |
| Wan2.2, LTX-video | MHA | no - nothing to expand |
| Qwen3.8 27B (llama.cpp) | GQA | no - llama.cpp has no GQA to MHA switch |
| Qwen-VL | GQA | not on disk |

The expansion from V100-19 is a separate CUDA kernel, and neither llama.cpp nor diffusers calls it. Hosting it means rebuilding a pipeline around the kernel and comparing frame time with and without it, which is a 4-6 hour job, not a flag flip.

**Verdict.** Unstated is the honest label here: the check had no carrier, which is not the same as "the effect does not exist". The kernel-level 7.2x from V100-19 stands and is untouched by this card.

**Result type.** Unstated.

**Does not show.** Anything about the end-to-end effect: neither its size nor its absence. No pipeline was modified, and no frame time was measured with the expansion in place.

**Raw.** [`raw/runs/V100-61.json`](../raw/runs/V100-61.json) - the inventory that produced the table above.

**Commands.** No run was made. The inventory was taken with directory listings of the model tree and attention-type inspection of the installed pipelines.
