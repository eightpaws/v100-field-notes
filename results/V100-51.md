# V100-51 — 32k context for 30B MoE on 16 GB

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** The 30B-A3B has a compact KV (GQA), so 32k can fit alongside 17.3 GB of weights if part of the experts are held in 96 GB RAM through -ncmoe. This is a direct response to the question "will there be enough context for the wrapper file."

**Result.** Qwen3-Coder-30B-A3B (17.3 GB, MoE 30B with 3.1 billion active parameters) on 16 GB holds 32k context only with expert offloading to CPU and compressed KV cache. llama.cpp master 51831d4, CUDA 12.9, `-c 32768`, single runs of 8 tokens each: | KV | experts on CPU | prompt | generation | |---|---|---|---| | fp16 | 24 | 50.8 tok/s | 16.6 tok/s | | fp16 | 32 | 27.9 | 9.5 | | **q8_0** | **16** | **39.5** | **25.2** | | q8_0 | 20 | 46.2 | 4.9 | Working setup for long context: `-c 32768 -ctk q8_0 -ctv q8_0 -ncmoe 16`. Compressed KV cache saves enough VRAM to hold more experts on GPU, and generation is faster than with fp16 at 24 experts on CPU. Numbers are single and noisy (spread for ncmoe=20 suspiciously large, likely swap), for accuracy a run of n=3 with real long prompt is needed. 16k context with the same settings should be noticeably faster.
