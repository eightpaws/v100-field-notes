# V100-88 - Volta flash-attention path is 5% slower than Triton in vLLM on sm_70

_Measured on a Tesla V100-SXM2 16 GB (sm_70), driver 580.178.04, inside a virtual machine with 24 vCPU and 94 GiB RAM._

**Question.** A community FlashAttention-2 port for SM70 (`zhinianqin/flash-attention-v100`) claims +580% prefill over TRITON_ATTN at 8k prompts. Its backend cannot be selected through the environment variable this engine ignores, so does the Volta flash-attention path that *is* reachable beat Triton at 8k and 16k, and by the claimed margin?

**Environment.**

| Item | Value |
|---|---|
| GPU | Tesla V100-SXM2-16GB, compute capability 7.0, 16 GiB |
| Driver / toolkit | 580.178.04 / CUDA 12.9 (fork built for `sm_70` only, g++-12 as host compiler) |
| Engine | vLLM 1.5.4 (1Cat build), torch 2.10.0+cu128 |
| OS / CPU | Ubuntu 24.04.5, kernel 6.8.0, 24 vCPU |
| Model | Qwen2.5-7B-Instruct GGUF, 5.44 GB, `load_format=gguf`, KV cache `int8_per_token_head` |
| Server flags | `--max-model-len 17408 --attention-backend <TRITON_ATTN or FLASH_ATTN_V100> --gpu-memory-utilization 0.90` |
| VRAM at steady state | 14 963 MiB (Triton) / 15 103 MiB (FLASH_ATTN_V100) of 16 384 MiB |
| Server start | 123 s (Triton) / 137 s (FLASH_ATTN_V100) |

**Commands.**

```bash
# Triton arm: the fork's SM70 baseline must be switched off or it takes over
VLLM_SM70_FLASH_ATTN_V100=0 /home/hermes/venvs/vllm/bin/python -m vllm.entrypoints.openai.api_server \
  --model /models/qwen2.5-7b-instruct.gguf --served-model-name qwen25-7b --max-model-len 17408 \
  --attention-backend TRITON_ATTN --gpu-memory-utilization 0.90 --port 18521 --host 127.0.0.1

# Volta arm
/home/hermes/venvs/vllm/bin/python -m vllm.entrypoints.openai.api_server \
  --model /models/qwen2.5-7b-instruct.gguf --served-model-name qwen25-7b --max-model-len 17408 \
  --attention-backend FLASH_ATTN_V100 --gpu-memory-utilization 0.90 --port 18522 --host 127.0.0.1

# prefill harness: unique prefix per repeat, length from the tokenizer, 3 repeats per length
python3 bench_v88c.py <port> /srv/media/night/v100_88b.jsonl <label> 8192 16384
```

The backend actually loaded is confirmed in each server log, not assumed: `AttentionBackendEnum.TRITON_ATTN backend` in one, `AttentionBackendEnum.FLASH_ATTN_V100 backend` in the other.

**Results.** Prefill throughput measured as wall time of a single-token completion over a long prompt; prompt length taken from the server's `usage.prompt_tokens`, with a unique prefix on every repeat so the prefix cache cannot answer.

| Backend | Prompt tokens | Wall time, s | Prefill, tok/s |
|---|---|---|---|
| TRITON_ATTN | 7 888 | 6.699 | **1 177.5** |
| FLASH_ATTN_V100 | 7 888 | 7.034 | 1 121.3 |
| TRITON_ATTN | 15 763 | 23.155 | **680.8** |
| FLASH_ATTN_V100 | 15 763 | 24.480 | 643.9 |

Triton is faster by 5.0% at 7.9k and 5.7% at 15.8k. The gap is small but repeatable: warm repeats within an arm agree to 1 ms, and the ordering does not flip between lengths.

**Repeats.** n=3 per length and per backend, first repeat discarded as warm-up. Warm repeats differ by less than 0.01% (6.699 / 6.699 s at 7.9k on Triton), so the spread is far below the measured 5% difference.

**Result.** On this card and this engine the reachable Volta flash-attention path is 5% slower than Triton for prefill, at both 8k and 16k. The +580% claim is not reproduced and not even matched: the sign of the effect is opposite, and the magnitude is two orders of magnitude off. Throughput still drops 42% between 7.9k and 15.8k tokens on both backends, which is the quadratic attention term, not a backend property.

**Verdict.** Negative: with backend selection done explicitly, Triton beats the Volta flash-attention path at every length measured, so the fork has nothing to offer on a single 16 GB V100 even before its own kernels run.

**Result type.** Negative.

**Does not show.** The fork's own kernels were never executed: its build was copied to `site-packages/vllm_flash_attn/` (md5 316b9609), while vLLM imports `vllm/vllm_flash_attn/` (md5 5cb925b1, dated 22 Nov), so the +580% claim is untested rather than refuted. Decode was not measured, only prefill. One 7B GGUF model at one KV-cache dtype was used; 27B and MoE models may order differently. The Triton arm needs `VLLM_SM70_FLASH_ATTN_V100=0` because the platform baseline otherwise overrides the explicit choice.
