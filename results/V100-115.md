# V100-115 — CI and Docker: how many repositories are being built

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Environment.** Guest AI-GPU on home stand (Ubuntu 24.04, 24 vCPU, 108 GB RAM), Docker 29.1.3 (docker.io package from apt, installed in this run, 2 min), base `python:3.12-slim` 179 MB, generator - Ollama `qwen2.5-coder-14b` (temperature 0.1, num_predict 1400), Python 3.12 in container, pip 25.0.1, ruff from PyPI (version not fixed), GPU V100 16 GB - only for model loading, builds run on CPU.

**Repeats.** Single run per project (n=1): Assembly and CI were measured once per project; build time was one measurement, variance was not removed (expensive builds were not rerun for standard deviation).

**Result.** 5 projects from previous cards (V100-109 FastAPI-notes, V100-114 static page, V100-116: api-client, CLI-ETL, FastAPI+JWT). First pass without edits: **0 out of 5**. Reproducible reasons: generated Dockerfile and ci.yml came in markdown-wrap (```dockerfile / ```yaml) and the image file was not built at all; in requirements made-up and non-existent versions (`uvicorn==0.16.3` not on PyPI, `passlib==1.0.6` instead of 1.7.x), stdlib as a package (`argparse==1.4.0`, `sqlite3==2.6.0`); static page Dockerfile put `pip install -r requirements.txt`, which is not in the repository; api-client `pytest` ran in build-stage, causing the image not to be created on red tests. After machine tuning (13 edits on 5 projects, 6 min) **4 out of 5 images are built**: p109 60.5s, api_client 33.6s, cli_etl 54.8s, fastapi_jwt 58.7s; the fifth (nginx, static page) is not built - Docker Hub registry cut off loading layer `nginx:alpine` (same cut-off was on `python:3.12-slim`, passed on second try). CI is not green **for any**: ruff `--select E,F` gives 67 (p109), 1 (api_client), 3 (cli_etl), 30 (fastapi_jwt) notes; pytest: 2 collection errors with p109 and fastapi_jwt (no `httpx` for `starlette.testclient`), 1 collection error with api_client, 1 crash with cli_etl (`NameError: name 'sqlite3' is not defined` - in generated code propan import). Separate defect of the framework: multi-stage Dockerfile from p109 copies only `/app` to runtime, dependencies remain in test-stage, i.e., the image is built but the application in it will not run. **Conclusion:** build closes with editing requirements and stage (machine, minutes), tests - no; half of the projects without edits CI does not pass in any aspect.
