# V100-72 — Agent with four tools and an error on the first call

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** The tool has been tested on one instrument and one step. Real tasks require two to three steps and recovery after incorrect arguments.

**Environment.** Llama-server + agent script with four tools; V100 16GB (sm_70), driver 580, CUDA 12.9

**Repeats.** single run

**Result.** 1 of 3 scenarios.** Three tasks, four tools, the first call `get_time` was intentionally broken (server responded with `unknown argument 'location'; the only valid argument is 'city'`. Error recovery worked: model repeated the call with the correct argument, on the first scenario made both steps (`get_time` + `calc`) - but the final answer did not contain the expected number and credit was not received. The second scenario (`read_file` + sum) was closed correctly. The third took `get_rate`, but did not call `calc` - calculated in mind, answer did not match. Result: agent loop works and fixes argument errors, but model cannot hold a chain of two calculations - it prefers to calculate itself. For agents, either a prompt "each calculation through calc" or external answer check is needed.
