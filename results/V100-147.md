# V100-147 — Cache prefix: equal prompt lengths

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** In V100-11, a comparison at 6k mixed the prompt length and cache effect: a cold call was 3368 tokens, while a non-cached call was 5045. If lengths are equalized, the cache gain will be less than the claimed 8x, and the publication will need to be corrected.

**Environment.** Llama-server 1.1.0-dev (build 1, commit 28148b5), V100-SXM2-16GB sm_70, driver 580.178.04, CUDA 12.9, model qwen2.5-7b-instruct.gguf (Q4), guest VM on local host, Ubuntu 24.04, kernel 6.8.0-151

**Commands.** `/root/bin/v100-run.sh V100-147 -- bash /root/v147_driver.sh`; inside `llama-server -m /models/qwen2.5-7b-instruct.gguf -ngl 99 -c 8192 -np 1 --cache-reuse 256 --port 18447 --host 127.0.0.1`; harness `/root/v147_harness2.py` takes length from `/tokenize` (prompt is passed as an array of token IDs), sends `/completion` with `n_predict: 1`, `temperature: 0`, `cache_prompt: true` and reads `timings.prompt_ms/prompt_n`.

**Artifacts.** /root/runs/V100-147/run.log, /srv/media/night/v100_147.json (27.11.2026 19:26 MSK)

**Repeats.** n=3, mean ± stdev; Cache miss was verified at `prompt_n=4096` (the first pass with a matching first token yielded `prompt_n=14` and did not enter the series).

**Result.**

**Verdict.** With a prompt length of 4096 tokens, prefix cache provides an **8.25x** speedup: without cache, 1179.8 ± 2.0 ms (full prefill of 4096 tokens, 3472 tok/s), repeating the same prefix 143.0 ± 1.2 ms (`prompt_n=1`, `cache_n=4096`).
