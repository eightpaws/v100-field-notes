# V100-66 — Quality over speed: MBPP on three models

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** All measurements in this session were in tok/s, yet none indicated which model genuinely produces correct code. Among the three candidates on a 16GB setup, with varying speeds, are: DeepSeek-Coder-V2-Lite at 183 tok/s, Qwen3-Coder-30B-A3B at 75 tok/s, and PXA 27B at 105 tok/s.

**Environment.** model_eval.py + llama-server, DeepSeek-Coder-V2-Lite 16B and others; V100 16 GB (sm_70), driver 580, CUDA 12.9

**Repeats.** single run

**Result.** Harness run of `model_eval.py`, one server ascent, 40 MBPP tasks + 8 blocks. DeepSeek-Coder-V2-Lite 16B (Q4_K_M, -fa 0, ctx 16k):** pass@1 **0.55** (22 out of 40), format 4/5, RAG 2/2, long context found (prompt 12,577 tokens), content **322 words instead of 550-650** - writes briefly, tool calling **0 calls** (no tool template in the model), honesty **fail**: confidently named `llama_sample_eg3` for non-existent speculation type, stability ok (3 out of 3 responses matched), speed pp2048 **2098 tok/s**, tg **183 tok/s**. Conclusion: suitable as a fast code writer and RAG responder, not suitable for toolchain agent sequences and long texts. **Comparison of two models on the same harness (24.11):** | Block | DeepSeek-Coder-V2-Lite 16B | Qwen3-Coder-30B-A3B | |---|---|---| | Code, pass@1 (40 MBPP tasks) | 0.55 | 0.53 | | Format, 5 tasks | 4/5 | 5/5 | | RAG (document + refusal) | 2/2 | 1/2 - missed 14-day deadline | | Long context | finds (12,5k) | finds (6k) | | Content 550-650 words | 322 words | 369 words | | Tool calling | 0 calls (no template) | valid call | | Honesty (non-existent API) | invented `llama_sample_eg3` | said "such function does not exist" | | Stability | ok | ok | | Speed | pp2048 2098 tok/s, tg 183 | tg 58.8 at ncmode 16 | Conclusion: DeepSeek is three times faster but doesn't handle tools and invents API; Qwen3-Coder is more disciplined and suitable for agent chains, but slow and misses RAG details. Both write shorter than required - need separate model or strict "not less than N words" with length check for articles.
