# V100-66 - Quality over speed: MBPP pass@1 on 16 GB models

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: EPYC 7282, 24 vCPU, 94 GiB RAM, driver 580.178.04, Ubuntu 24.04.5._

**Question.** Every earlier measurement in this series counted tok/s, and none answered which model on a 16 GB card actually writes correct code. Hypothesis: the fastest model of the three candidates is not the one with the highest pass@1, and the ranking by tokens per second misleads. Success metric: pass@1 over the sanitized MBPP set, winner decided by pass@1 with speed as the second criterion.

**Environment.** Tesla V100-SXM2-16GB, compute capability 7.0, 16384 MiB; driver 580.178.04; CUDA 12.9 (`/home/hermes/cuda-12.9`); llama.cpp build129 (CUDA, sm_70); Ubuntu 24.04.5, kernel 6.8.0-151, Python 3.12.3. Harness `/root/code_eval.py` - one entry point for every engine, tests executed locally in a subprocess. Dataset `/srv/media/ai-cache/eval/mbpp.jsonl` (sanitized MBPP, 40 and 200 task runs). Decoding: temperature 0, code-only prompt.

Models: `deepseek-coder-v2-lite-q4_k_m.gguf` (10.4 GB, context 4096), `qwen3-30b-a3b.gguf` (18.6 GB, context 8192, `-ngl 99 -ncmoe 8`, 15 991 MiB VRAM).

**Commands.**

```
python3 /root/code_eval.py --base-url http://127.0.0.1:18311 --model qwen --tasks 40
python3 /root/code_eval.py --base-url http://127.0.0.1:18311 --model qwen --tasks 40 --no-think
python3 /root/code_eval.py --base-url http://127.0.0.1:18311 --model qwen --tasks 200 --no-think
```

Server for the 30B runs: `llama-server -m /models/qwen3-30b-a3b.gguf -ngl 99 -ncmoe 8 -c 8192 --host 127.0.0.1 --port 18311`. Exact server flags of the DeepSeek runs were not preserved; the request shape above is what the harness issued (chat completions, temperature 0, `max_tokens` 512 on the 40-task runs of the dense model, 700 on the reasoning-on run).

**Results.**

| Configuration | Tasks | pass@1 | Passed | s/task | tok/s |
|---|---|---|---|---|---|
| DeepSeek-Coder-V2-Lite 16B Q4_K_M | 40 | **0.55** | 22/40 | 0.5 | - |
| Qwen3-Coder-30B-A3B, reasoning on | 40 | 0.225 | 9/40 | 7.97 | 78.4 |
| Qwen3-Coder-30B-A3B, reasoning off | 40 | **0.60** | 24/40 | 0.89 | 59.7 |
| Qwen3-Coder-30B-A3B, reasoning off | 200 | **0.50** | 100/200 | 0.92 | 59.3 |
| DeepSeek 16B, pre-fix harness | 40 | 0.10 | 4/40 | 0.4 | - |

Two findings decided the whole card. First, the reasoning mode of Qwen3 is not free: with thinking on, the same model answered for 7.97 s per task and scored 0.225 instead of 0.60 - it burns the token budget on thoughts and never finishes the code. With `chat_template_kwargs.enable_thinking=false` it answers in 0.89 s and scores 0.60. Second, the 40-task figure is optimistic: on 200 tasks the same configuration lands at 0.50, and that is the number to quote.

The 0.10 row is a harness bug, not a model result: the first pass of the dense model scored 4/40 because the answer parser rejected valid blocks. After the fix the same weights scored 22/40 twice. It is kept here because a reader comparing this card with an older note will otherwise see a contradiction.

**Repeats.** Single run, not repeated.

**Result type.** Mixed.

**Verdict.** Reasoning mode costs 6x the time and 37 points of pass@1 unless it is disabled; with thinking off the 30B MoE reaches 0.60 on 40 tasks but 0.50 on 200, level with the 16B dense model at 0.55.

**Does not show.** Single run per configuration - repeat series were not measured, so the spread between runs is unknown. At 40 tasks and p about 0.5 the 95% confidence interval is roughly plus or minus 0.15, which is wider than every difference in the table except the reasoning on/off gap; only the 200-task run is tight enough to separate models. Accuracy is measured on short Python functions from MBPP only - no multi-file tasks, no repository context. Tool calling, format and RAG blocks from the earlier wiki note came from a different harness whose outputs were not archived, and are not claimed here.

**Raw.** [raw/runs/V100-66.json](raw/runs/V100-66.json) - five configurations with per-task pass/fail, seconds and completion tokens, built from the run JSONs on the rig (`v100_66_deepseek16c.json`, `v100_66_deepseek16.json`, `strata/baseline-qwen3-30b-{mbpp,nothink-mbpp,nothink-mbpp-200}.json`).
