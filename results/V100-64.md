# V100-64 — Snapshot of stack: offline installation on clean VM

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Setting up from a snapshot without network will bring up all three pipelines; if not, the snapshot is missing packages, which should be known before updating, not after.

**Environment.** Guest AI-GPU on home bench, Ubuntu 24.04, kernel 6.8.0-151-generic, Python 3.12.3, driver 580.178.04, nvcc release 12.9 (`/home/hermes/cuda-12.9`), pip from fresh venv; network removed `unshare -n` (only loopback remains, DNS not responding).

**Commands.** `/root/bin/v100-run.sh V100-64 -- bash /root/v100_64_offline.sh`; inside `unshare -n bash -c "/root/venvs/off64-dry/bin/pip install --dry-run --no-index --find-links /srv/media/ai-cache/wheels -r /srv/media/ai-cache/wheels/requirements-video.txt"` and `unshare -n bash -c "python3 -m venv /root/venvs/off64-core && /root/venvs/off64-core/bin/pip install --no-index --find-links /srv/media/ai-cache/wheels 'torch==2.10.0+cu128' 'torchvision==0.25.0+cu128' 'torchaudio==2.10.0+cu128' diffusers transformers accelerate safetensors"`.

**Artifacts.** [raw/runs/V100-64.json](../raw/runs/V100-64.json) (numbers from logs), full logs on VM: /root/runs/V100-64/run1.log, /root/runs/V100-64/run.log, dryrun.log, core_install.log, core_install_b.log; scripts /root/v100_64_offline.sh, /root/v100_64_step4b.sh.

**Repeats.** Determined cache completeness check, second pass resulted in same failure on `filelock`.

**Result.** No: the snapshot does not stand the stack up without the network. The cache holds 12 wheels (2,3 GB) that cover 8 of 302 lines in the full freeze (2,6 %) and 15 of 45 in `acestep/requirements.txt` (33 %). Installing the full freeze dies on the third line (`-e git+https://github.com/ace-step/...` needs the network), and the positive control `torch==2.10.0+cu128` dies on `filelock` because no transitive dependency is cached at all, including the 42 `nvidia-*` packages in the freeze.
**Verdict.** Negative for the snapshot as built: it should have captured 23 GB (the three live virtualenvs are 8,4 + 14 + 1,0 GB), not 2,3 GB. The run took 15 s, used no GPU and left 63 of 193 GB on the root disk.

**Result type.** Mixed.
