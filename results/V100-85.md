# V100-85 — Xing4.0-29B-A4B in IQ2_M

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Xing4.0-29B-A4B (64 experts, 4 active, MLA + MoE + MTP, 256K context, Apache 2.0) weighs 11.8 GB in IQ2_M and should leave room for KV cache and an expert cache in 16 GB. The official IQ4_NL (19.2 GB) does not fit. Does the 2-bit quant keep code quality above the card's bar of MBPP pass@1 0.55 at 60 tok/s or better?

**Environment.** `llama.cpp` build 400, commit dbaf582 (the `llama-inkling` build directory on the stand), compiled with CUDA 12.9 for sm_70; driver 580.178.04; Tesla V100-SXM2 16 GB; Ubuntu 24.04 guest. Weights: `xing4_0-29b-iq2_M-slim.gguf`, 11,800,813,760 bytes, sha256 `eab889…be312` verified against the Hugging Face `lfs.oid`, stored on the SSD pool. The card was cleaned to 0 MiB before every run.

**Commands.**
```
llama-bench -m /srv/ssd-strata/xing4/xing4_0-29b-iq2_M-slim.gguf \
  -ngl 99 -p 512 -n 128 -r 2 -fa 0 -o json          # repeated with -fa 1

llama-server -m /srv/ssd-strata/xing4/xing4_0-29b-iq2_M-slim.gguf \
  -ngl 99 -c 8192 --jinja --host 127.0.0.1 --port 18431 -t 8

python3 /root/code_eval.py --base-url http://127.0.0.1:18431 --model xing4 \
  --tasks 40 --no-think --max-tokens 1536 --out /srv/media/night/v100_85_mbpp2.json
```
The whole 11.8 GB model sits in VRAM: no expert offload flag is needed, which is the point of the 2-bit file.

**Repeats.** Not recorded: repeatability was not documented for this run - treat the numbers as a single run unless the result says otherwise.

**Results.** Prefill 512 tokens: 1,949 tok/s with `-fa 0` and 1,877 with `-fa 1`. Decode 128 tokens: 71.4 tok/s and 64.1. MBPP pass@1 **0.425** (17 of 40), 1.84 s per task, 44.2 tok/s average generation inside the eval; VRAM 11.2 GB, server ready in 6 s. The first pass scored 0.05 (2/40) and that number is a harness artifact: every row reports `tok=512`, the default chat template enables reasoning, and all 40 answers hit the token cap before the code block started. With `chat_template_kwargs.enable_thinking=false` and 1,536 tokens the same build scores 0.425.

**Verdict.** Negative. The 2-bit quant does what it promises on memory - a 29B MoE resident in 16 GB at 71 tok/s decode - but code quality lands at 0.425, below the card's 0.55 bar and below even a 7B model at Q8_0 (0.625) and a 7B in 4-bit AWQ (0.50). Worth keeping only as a fast drafter or summarizer, not as a coding model.

**Result type.** Negative.

**Does not show.** Only IQ2_M was measured; IQ3_XXS (13.99 GB) and IQ3_M (15.45 GB) also fit this card and were not run, so 0.425 is a property of this quant, not a curve. MBPP is a single run of 40 Python tasks at temperature 0 with no repeats, so one task is worth 2.5 points and the interval is wide. No long-context test of the advertised 256K window, no check of the MTP head, and no profile of the MLA attention path - a silent slow path, as happened with GQA on this card, cannot be ruled out from these numbers. Generation speed inside the eval (44.2 tok/s) includes prompt handling and is not comparable to the 71.4 tok/s decode figure from `llama-bench`.

**Raw.** `raw/runs/V100-85.json` - both `llama-bench` configurations, both MBPP passes with per-task rows, model size and sha256.
