# V100-85 — Xing4.0-29B-A4B in IQ2_M

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Xing4.0-29B-A4B (64 experts, 4 active, MLA+MoE+MTP, 256K context, Apache 2.0) weighs 11.8 GB and leaves space for KV and expert cache in IQ2_M. Official IQ4_NL (19.2 GB) does not fit into 16 GB.

**Environment.** Llama.cpp build 400 (commit dbaf582, build `llama-inkling`, CUDA 12.9, sm_70), driver 580.178.04, Tesla V100-SXM2 16GB, guest ai-gpu (24 vCPU, 94GB RAM), Ubuntu 24.04.

**Repeats.** Run `-r 2` on each FA configuration; MBPP - single run on 40 tasks, temperature 0.

**Result.** MBPP pass@1 **0.425** (17/40) at 44.2 tok/s generation and 1.84 sec per task; bench decode 71.4 tok/s (fa off) and 64.1 (fa on), prefill 512 - 1949 and 1877 tok/s, VRAM 11.2 GB, server boot time 6 sec. Card threshold (pass@1 ≥ 0.55 at decode ≥ 60 tok/s) not met for quality: 2-bit IQ2_M lags behind both 7B Q8_0 (0.625), and 4-bit AWQ (0.50). First run gave 0.05, but this is an artifact of the limit, not the model: all 40 responses hit the 512 token limit because reasoning was enabled by default and the code didn't have time to start; with `enable_thinking=false` and 1536 tokens - 0.425.
