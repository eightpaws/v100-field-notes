# V100-01 — Speculative decoding in llama.cpp: slower on both targets

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a virtual machine: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Decoding on this card is limited by 900 GB/s of memory bandwidth: every generated token reads all weights. If one pass verifies several candidate tokens, weights are read less often and time per token falls. Success criterion: 1.3-1.8x on qwen2.5-coder-14b Q4 (66 to 85-120 tok/s), a smaller gain on 7B because it is already fast.

**Environment.**

| Item | Value |
|---|---|
| GPU | Tesla V100-SXM2-16GB, compute capability 7.0, 16384 MiB |
| Driver | 580.178.04 |
| Engine | llama.cpp 1.0.0-dev, build 1224, commit 51831d47 (`/root/llama-old/build/bin/llama-server`) |
| CUDA | 12.9 toolkit; the binary was built with 12.9 for sm_70 |
| Host | Ubuntu 24.04.5 LTS, kernel 6.8.0-151-generic, 24 vCPU, 94 GiB RAM |
| Models | target: Qwen2.5-Coder-7B-Instruct Q4_K_M (4.4 GiB), Qwen2.5-Coder-14B-Instruct Q4_K_M (8.99 GB); draft: Qwen2.5-0.5B-Instruct Q8_0 (676 MB) |
| Server flags | `-ngl 99 -c 4096 -np 1`, one slot, `-lv 2` |
| Sampling | temperature 0, `n_predict` 96, `cache_prompt` false |

**Commands.** Baseline and speculative arms differ only in the draft flags (`$M` is the target GGUF, `$P` the port):

```
/root/llama-old/build/bin/llama-server -m $M -ngl 99 -c 4096 -np 1 --host 127.0.0.1 --port $P -lv 2
/root/llama-old/build/bin/llama-server -m $M -ngl 99 -c 4096 -np 1 --host 127.0.0.1 --port $P -lv 2 \
  --spec-type draft-simple -md /srv/media/ai-cache/downloads/qwen2.5-0.5b-instruct-q8_0.gguf \
  --spec-draft-ngl 99 --spec-draft-n-max 8
```

Each request is a plain completion call; `decode_tok_s` below is the `predicted_per_second` field that llama-server returns in the `timings` object of `/completion`:

```
curl -s http://127.0.0.1:$P/completion -H 'Content-Type: application/json' \
  -d '{"prompt":"...","n_predict":96,"temperature":0,"cache_prompt":false,"stream":false}'
```

**Results.**

| Target | Arm | Decode tok/s, mean ± stdev (n=3) | Delta | Draft acceptance | VRAM peak |
|---|---|---|---|---|---|
| Qwen2.5-Coder-7B Q4_K_M | baseline | 121.10 ± 0.28 | - | - | 4897 MiB |
| Qwen2.5-Coder-7B Q4_K_M | draft 0.5B Q8 | 60.83 ± 0.21 | **-49.8%** | 0.239 | 5493 MiB |
| Qwen2.5-Coder-14B Q4_K_M | baseline | 67.40 ± 0.07 | - | - | 9407 MiB |
| Qwen2.5-Coder-14B Q4_K_M | draft 0.5B Q8 | 39.62 ± 0.05 | **-41.2%** | 0.199 | 10005 MiB |

Per-request numbers are in the raw file; the spread inside a configuration is a tenth of a tok/s, so the gap is far outside the noise.

**Result.** Speculation never paid off here. On 14B the reproduction matches the original run of 2026-11-23 (67.0-67.6 baseline against 35.9-38.6 with the draft, acceptance 0.167-0.185). On 7B the original run reported 111.5-114.2 baseline and 134.6-140.3 with the draft, a +21% gain; that arm has no archived log, and today the same build and the same draft flags give 121.10 baseline against 60.83 with the draft, a 50% loss. The +21% figure is therefore withdrawn: with acceptance around 0.2 the draft is weaker than the target, so verifying eight candidates costs more than it saves, and a 0.5B Q8 draft throws away the token budget that a cheaper target would spend anyway.

**Verdict.** A 0.5B Q8 draft under `--spec-type draft-simple` makes decoding slower on this card for both a 7B and a 14B Q4 target, and the earlier +21% on 7B does not reproduce.

**Result type.** Negative.

**Does not show.** Only one draft model was tested (0.5B Q8); 1.5B drafts, `n-max` other than 8, batch above one slot, and code or tool-call prompts with a higher acceptance rate are unmeasured. The reason for the discrepancy with the 2026-11-23 7B arm is unknown: its log was not archived, so a different flag set in that run cannot be excluded, and today's flag set is the one quoted in the card text.

**Follow-up.** The 7B arm needs a draft-size sweep (0.5B and 1.5B at `n-max` 4 and 8) before this engine pair is written off for small targets; that sweep is not queued yet and this card will be rewritten when it lands.
