# V100-16 — volta-fa patches for llama.cpp: measured, not promised

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** `Frostbite1536/volta-fa` advertises +34–45 % on exactly this workload — one user, 8–16 tokens per
batch, long context — through eight small patches against a pinned llama.cpp commit: FA test crashes on sm_70,
GQA on small batches, quantized KV, prefill at head dimension 256, a new tensor-core matmul for K-quants. Does
the advertised gain reproduce on a real card?

**Environment.**

| Component | Value |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2-16GB, 16384 MiB / 580.178.04 / 7.0 (sm_70) |
| Base | llama.cpp at commit `79e2e74`, patch set `Frostbite1536/volta-fa` |
| Build | CUDA 12.8, `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 -DCMAKE_BUILD_TYPE=Release` |
| Baseline | Ollama 0.40.16 on the same GGUF |
| Model | qwen2.5-coder-14b, Q4_K |
| Host | Proxmox VE VM — 24 vCPU (EPYC 7282), 94 GiB RAM, Ubuntu 24.04.5, kernel 6.8.0-151 |

**Commands** (verbatim from the build script):

```bash
# 4 of 8 patches applied; the rest refused because the patches do not name their base commit
git am 000*.patch

cmake -S llama.cpp -B build-volta \
  -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 -DCMAKE_BUILD_TYPE=Release
cmake --build build-volta --config Release -j 24 --target llama-bench

build-volta/bin/llama-bench -m /models/qwen2.5-coder-14b.gguf -p 512 -n 128 -ngl 99 -fa 1
build-volta/bin/llama-bench -m /models/qwen2.5-coder-14b.gguf -p 4096 -n 128 -ngl 99 -fa 1
```

Baseline: the same prompts through Ollama's `/api/generate` on `qwen2.5-coder-14b:latest`.

**Results.**

| build | decode tok/s | prefill 512, tok/s | prefill 4096, tok/s | patches applied |
|---|---|---|---|---|
| Ollama (upstream) | 65.8 | 1776 | — | 0 |
| llama.cpp + FlashAttention | 70.65 | 1822 | 1663 | 4 of 8 |

**Repeats.** Single run per build, `n=1`. The two builds differ in more than the patches (Ollama's own runtime is
not the same binary), so this is a field comparison, not a controlled A/B.

**Verdict.** The promised +34–45 % is not there: +7.4 % on decode and +2.6 % on prefill, and most of that is
FlashAttention itself (+8.7 % on decode), not the Volta patches. Moving off Ollama for 7 % is not worth the
maintenance burden of a pinned fork — but 4 of 8 patches not applying is the more useful finding: the patch set
has no recorded base commit, so it cannot be rebased forward without manual work.

**Raw.** The binary was not preserved (the build lived in `/tmp`), and no bench JSON was kept.
