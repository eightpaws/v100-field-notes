# V100-55 — Llama-Bench refuses to load more than 20 layers.

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** This is OOM weight allocation, not TULA check; the pass-through boundary lies between 20 and 40 layers.

**Environment.** llama.cpp, Qwen3-Coder-30B-A3B Q4_K_M (17.28 GB), f16 KV, `-ncmoe 24` and `32`; V100 16 GB (sm_70), driver 580, CUDA 12.9

**Commands.** llama-bench. (Russian note in the field notes is omitted from this English export.)

**Artifacts.** Logs were not preserved for this run.

**Repeats.** single run (llama-bench, r=1)

**Result.** There is no limit of 20 layers.** The matrix is based on Qwen3-Coder-30B (17.28 GiB), f16 KV, p128/n16: | ncmoe | prefill pp128 | decode tg16 | |---|---|---| | 24 | 179.2 | 39.2 | | 32 | 145.2 | 34.6 | Both configurations load and calculate: the limit is not in the number of layers, but in the memory for context and computational buffers. With a large context (8k), failure occurs earlier - this was mistakenly considered as the "limit of 20 layers": at 8k, buffers are insufficient already at 8 layers (V100-65). Therefore, the number 20 refers to a specific context, not the architecture.
