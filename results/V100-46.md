# V100-46 — Tool calling on a local V100 model

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Can a locally served model emit a valid tool call, consume the tool result and answer, without a hosted API?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-server -m qwen3-coder-30b-a3b-q4_k_m.gguf -ngl 99 -ncmoe 8 -fa 0 -c 4096 --jinja --port 18081
curl -X POST http://127.0.0.1:18081/v1/chat/completions -d @tools.json
```

**Results.**

| Step | Result |
|---|---|
| First response | `tool_calls: [{name: get_time, arguments: {"city":"Moscow"}}]`, content empty |
| After tool result | no second call, answer "It is 23:41 in Moscow." |
| Full round trip | 4.99 s for two requests |

**Repeats.** single conversation, one tool schema

**Verdict.** Tool calling works correctly with the Qwen3-Coder chat template: valid JSON arguments, no extra calls, correct final answer. At 75 tok/s decode a conversational turn costs 2–3 s.

**Result type.** Positive.

**Does not show.** Only one tool and one turn were exercised; multi-turn agent loops with several tools, malformed arguments and error paths were not tested.
