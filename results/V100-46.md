# V100-46 — Tool calling: a five-task battery instead of one request

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Which locally served models actually call tools and finish a small task without a human — and where does the chain break? The earlier version of this card answered only "does it emit a tool call at all", with a single request.

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp build129, HEAD `b1b770d90` (binary built 2026-11-27) |
| Server flags | `--jinja`, `-ngl 99 -c 8192 -t 8`, `-ncmoe 8` for the 30B MoE |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Test runner | pytest 9.2.0 (project venv) |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |

**Commands.**

```bash
v100-run.sh V100-46 -- /root/venvs/app/bin/python3 /root/v100_46.py
# inside the harness, one server per model:
llama-server -m /models/qwen2.5-coder-14b.gguf  -ngl 99 -c 8192 -t 8 --jinja --host 127.0.0.1 --port 18561 --no-webui
llama-server -m /models/qwen2.5-7b-instruct.gguf -ngl 99 -c 8192 -t 8 --jinja --host 127.0.0.1 --port 18562 --no-webui
llama-server -m /models/qwen3-30b-a3b.gguf      -ngl 99 -c 8192 -t 8 --jinja --host 127.0.0.1 --port 18563 --no-webui -ncmoe 8
# requests: POST /v1/chat/completions with tools, max_tokens 900, temperature 0,
# Qwen3 additionally chat_template_kwargs {"enable_thinking": false}
```

**Results.** Five sandbox tasks per model, four real file tools (`list_files`, `read_file`, `write_file`, `run_tests`), up to six steps per task. Pass/fail is objective: the harness runs pytest itself and also checks that the task's test files were not edited.

| Model | Tasks passed | Tool calls | Bad JSON args | Repeated identical calls | Where the chain broke |
|---|---|---|---|---|---|
| qwen2.5-coder-14b | 0 / 5 | 0 | 0 | 0 | never used the tool channel: printed `{"name": "run_tests", "arguments": {}}` as text in `content`, in all five tasks, although the chat template declares tools (2 506 chars, the word `tools` is present) |
| qwen2.5-7b-instruct | 2 / 5 | 18 | 0 | 0 | wrote a broken `cart.py` while fixing `total_with_tax` (pytest collection error), and on the multi-file task rewrote `app/models.py` with fabricated data so the test would pass |
| qwen3-30b-a3b (`-ncmoe 8`) | 2 / 5 | 6 | 0 | 0 | on the fix task it stopped and asked the human for logs; on the add-function task it passed a file name to `list_files` instead of a directory; on the multi-file task it read both files and answered without editing |

| Task | What it checks | 14B | 7B | 30B |
|---|---|---|---|---|
| t1 | name the failing function, no edits | fail | pass | pass |
| t2 | make failing tests pass | fail | fail | fail |
| t3 | add `median()` so hidden tests pass | fail | pass | fail |
| t4 | two-file bug fix | fail | fail | fail |
| t5 | false premise: tests already pass | fail | fail | pass |

Three models, five tasks, 85 s of wall time on the card, server load 2.0-4.3 s per model from page cache.

**Repeats.** Two series of 85 s. The first series is discarded for every task checked by pytest: the harness took the exit code of `tail` in the pipeline instead of pytest's, so "fixed" was scored for free. t1 and t5 are text checks and came out identical in both series. `single run` for the valid series.

**Result.** Argument formatting is not the problem: 0 malformed JSON and 0 repeated identical calls across 24 tool calls. Task success is: 2/5 for Qwen2.5-7B-Instruct and Qwen3-30B-A3B, 0/5 for Qwen2.5-Coder-14B, whose GGUF declares tools in the template but never uses the tool channel. Failures are strategic, not syntactic: a model stops to ask the human, passes a file where a directory is expected, edits tests or data to make a test green, or writes a module it cannot import.

**Verdict.** Tool calling on this rig is mechanically reliable (JSON arguments, no loops) but only 2 of 5 tasks finish unattended, and a coder-tuned 14B that never emits a tool call is unusable in an agent loop regardless of its code quality.

**Result type.** Mixed.

**Does not show.** The sandbox is 2-4 files, not a real repository; all five tasks are Python; the "0 malformed JSON" figure covers 24 calls and says nothing about longer chains; the spread between the two series is not separated from sampler non-determinism at temperature 0; VRAM peak was not sampled.
