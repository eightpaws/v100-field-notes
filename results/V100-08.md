# V100-08 - Text-to-SFX on a V100: Stable Audio Open vs the open alternative

**Question.** A product video without a sound layer reads as cheap. Can a 16 GB Volta card generate short sound effects (rustling paper, water, footsteps, room ambience) fast enough to use in the video pipeline, and does fp16 on a card without native fp16 acceleration add audible noise?

**Environment.**

| | Value |
|---|---|
| GPU | Tesla V100-SXM2 16 GB, cc 7.0 (sm_70) |
| Driver / OS | 580.178.04 / Ubuntu 24.04, python 3.12 |
| Engine | diffusers 0.39.0, transformers 4.57.6, torch 2.10.0+cu128 |
| Model | `cvssp/audioldm2`, 3.5 GB (safetensors only) |
| cuDNN | disabled (`torch.backends.cudnn.enabled = False`): cuDNN 9 has no convolution engine for sm_70 |

Stable Audio Open 1.0 was the original idea; its weights are gated on Hugging Face and both `huggingface.co` and `hf-mirror.com` answer **401** without an account token (`model.safetensors`, 4.85 GB). The open model of the same class, AudioLDM2, was used instead.

**Commands.**

```
/root/bin/v100-run.sh V100-08 -- /home/hermes/acestep15/.venv/bin/python /root/gen_sfx.py
```

What the script does (verbatim core):

```python
pipe = AudioLDM2Pipeline.from_pretrained("/srv/media/audioldm2", torch_dtype=torch.float16).to("cuda")
audio = pipe(prompt=p, num_inference_steps=100, audio_length_in_s=10).audios[0]
```

`transformers` 4.57 moved `_update_model_kwargs_for_generation` into `GenerationMixin`, so the GPT-2 language model inside the AudioLDM2 pipeline raises `AttributeError`. The run needs a three-line patch that restores the old method on `GPT2Model`; without it the pipeline fails before the first sampling step.

**Results.**

| Metric | fp16 (5 clips) | fp32 control (2 clips) |
|---|---|---|
| Synthesis per 10 s clip | 9.3 ± 0.22 s (min 9.2, max 9.7) | 10.0 s and 9.5 s |
| Real-time factor | 0.93 | 1.00 / 0.95 |
| VRAM peak | 2.86 GB | 2.86 GB |
| Model load | 3.1 s | 2.2 s |
| Output | 16 kHz mono | 16 kHz mono |
| NaN / clipping | none | none |

Amplitude and spectral character are the same in both precisions (RMS -16.3 to -27.8 dBFS, spectral centroid 3.5-5.5 kHz, flatness 0.52-0.67), and the spectrograms of the fp32 pairs show no extra bands or clicks - fp16 adds no visible noise on this card. Three of five clips carry a usable event structure (a gated series of bursts for the shears, a drop-out in the water clip, rhythmic attacks for footsteps); the two ambience prompts come out as stationary broadband noise, which is the model's character rather than a precision artifact.

**Repeats.** fp16 synthesis `n=5, mean 9.3 s ± 0.22 s`; fp32 control `n=2` (10.0 and 9.5 s). Quality was judged from spectrograms and level statistics, not by listening.

**Verdict.** Mixed: text-to-SFX on this card is real and cheap (one second of audio per 0.93 s, 2.9 GB VRAM, so a whole video's ambience layer costs seconds), but AudioLDM2 tops out at **16 kHz mono** and is noise-heavy on ambience prompts, which fits background texture and short accents, not precise synchronisation. Stable Audio Open (44.1 kHz stereo, up to 47 s) remains untested because its weights are gated.

**Result type.** Mixed.

**Does not show.** No listening test was done, so "usable" here means "structure visible in the spectrogram and levels in range", not "sounds right". Only 100 sampling steps were run (the pipeline default is 200), so quality at the default setting is not measured. The comparison is between two different models, not two precisions of one model - the fp16/fp32 pair is the only like-for-like comparison in this card. No muxing into an actual video was tried, so clicks at clip boundaries are unverified.
