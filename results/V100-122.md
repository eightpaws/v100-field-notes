# V100-122 — Stability of output: five repeats of one task

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Environment.** V100 16 GB (sm_70), driver 580, llama.cpp build129 (af5c583), model Qwen2.5-Coder-7B-Instruct Q8_0, -c 8192, -ngl 99, fresh llama-server per run

**Repeats.** n=5 at temperature 0 (seed 42) and n=5 at 0.2 (seed 1006-1010), with 12 tests per run

**Result.** 5 runs at temperature 0 produced byte-for-byte identical files (110 lines, sha 250c6b60), at 0.2 - five different ones (73-115 lines, average 97), so repeatability at 0 is absolute, and at 0.2 the format varies by ±40% lines. Out of 12 tests in each of ten runs, only 4 passed: the criterion "not less than 4 successful out of 5" was not met (0 out of 5 at both temperatures). The defect occurs in all ten files: `next()` constructs `self.tasks.index(x)` when `self.tasks` is a dictionary and raises AttributeError, loading in the constructor falls with TypeError, therefore CLI `stats` on existing file does not work. Only add with pending counter passed, KeyError on unknown id, ValueError on broken JSON and empty next() = None.
