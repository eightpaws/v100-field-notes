# V100-37 — 32B dense and 30B MoE: re-measuring decode at 96 GB

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 96 GB RAM, driver 580._

**Hypothesis.** The conclusions «qwen2.5-32b - 7 tok/s, offloading to RAM kills speed» and «30B-A3B - 35 tok/s hybrid» were obtained with 32 GB used up to the ceiling: the CPU part of the weights competed with the page cache rather than residing resident. With 96 GB, it should remain in memory.

**Test rig.** Tesla V100-SXM2-16GB (cc 7.0, 16384 MiB) · driver 580.178.04 · Ubuntu 24.04.5, kernel 6.8.0-151 · EPYC 7282, 24 vCPU, 94 GiB RAM · Python 3.12.3 · ollama: KV_CACHE_TYPE=q8_0, NUM_PARALLEL=4, KEEP_ALIVE=30m, MAX_LOADED_MODELS=1

**Commands.** `llama-bench` with `-ngl` 20 / 40 / 99 for dense 32B Q4 (18.5 GB) and MoE qwen3-30b-a3b Q4 (17.3 GB).

**Artifacts.** [raw/runs/V100-37.json](../raw/runs/V100-37.json)

**Repeats.** single run on configuration

**What is needed.** The same GGUF, Ollama, and llama.cpp with an explicit number of layers on GPU and CPU, `--n-cpu-moe` for MoE, cold and warm run measurements.

**How it was verified.** decode tok/s, VRAM, RSS. Criterion: for 32B >10 tok/s or 30B-A3B >40 tok/s - then the verdict "does not fit" is rewritten.

**Risks.** If there is no difference, then the bottleneck was at PCIe ×8 and RAM bandwidth - the conclusion stands, and this needs to be recorded to avoid returning.

**Result.** The ceiling is at 16 GB of VRAM even with 96 GB RAM. Dense 32B Q4 (18.5 GB) model with 20 layers on GPU: prefill 253, decode 3.0 tok/s; at 40 and 99 layers llama-bench fails to load the model at all. MoE qwen3-30b-a3b (17.3 GB) with the same 20 layers: prefill 440, decode 24.5 tok/s - 8 times faster. Conclusion: among large models, only MoE can run on 16 GB VRAM; dense 30B+ models are not worth loading.
