# V100-145 — Gemini 4 26B-A4B in 4 bits: 16-GB sweet spot on Volta

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Survey of nine models on 8/16/24 GB named Gemma 4 26B-A4B as the best for 16 GB: best code among those that fit entirely, around 170 tok/s on a card with 1008 GB/s. V100 has 900 GB/s, so the numbers should be transferable.

**Environment.** V100-SXM2-16GB (sm_70), driver 580.178.04, CUDA 12.9, llama.cpp build129 (CUDA sm_70), AI-GPU testbed

**Commands.** `llama-bench -m gemma-4-26B_q4_0-it.gguf -p 256 -n 64 -r 3`; `llama-server -m gemma-4-26B_q4_0-it.gguf -ngl 99 -c 8192 --host 127.0.0.1 --port 18496 -t 8 --jinja`; `python3 /root/code_eval.py --base-url http://127.0.0.1:18496 --model gemma4 --tasks 40 --max-tokens 700 --no-think --out /srv/media/night/v100_145.json`.

**Artifacts.** /srv/media/night/v100_145.json (5946 B, 26.11.2026 22:27 MSK); directory /root/runs/V100-145 does not exist - run was from chat session, runner log was not saved.

**Repeats.** `llama-bench -r 3` for prefill and decode; three separate runs of 128 tokens for server number; MBPP - one run on 40 tasks. Card added retroactively based on already published `results/V100-145.md`: measurement was taken and posted, but not in queue, so not counted in progress reports.

**Result.** Fits entirely and fastest among those measured on this map: prefill 2696.3 ± 94.7 tok/s on pp256, decode 124.09 ± 0.53 tok/s on tg64, peak VRAM 15331 MiB at 8k context, server ready in 5s. Through HTTP API decode 105.1 / 107.5 / 107.3 (average 106.6) tok/s, MBPP pass@1 0.575 (23/40) at 100.4 tok/s and 0.9s per task. Against Flash-Next MoE (V100-130), which offloads experts to RAM: 45.1 tok/s decode and 90s warm-up. Result: 2.4x decode and 3.5x prefill with equal or better code quality (0.575 vs 0.51); reason structural - model entirely in 15.3 out of 16 GB, PCIe not involved in decode.
