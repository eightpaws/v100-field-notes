# V100-154 — Does RPC pay off when it doesn't fit into one card?

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** RPC layout costs 25-40% of speed on a model that fits on one card (V100-31); if a 16GB quantum does not fit, a pool of two machines should pay off because there is no alternative.

**Environment.** Tesla V100-SXM2-16GB, sm_70, driver 580, CUDA 12.9; llama.cpp 1.0.0-dev, commit b1b770d (`/root/llama.cpp/build/bin`), llama-bench; model `Qwen3.8-27B-UD-Q5_K_M.gguf`, 19,870,878,624 bytes (18.50 GB, 27.32 billion, 65 blocks, GQA 24/4, context 262,144); guest 24 vCPU / 94 GiB RAM, weights on `/srv/media`.

**Commands.** `LD_LIBRARY_PATH=/root/llama.cpp/build/bin llama-bench -m /srv/media/ai-cache/downloads/qwen38-27b-ud-q5km.gguf -p 4096 -n 128 -ngl 48 -fa on -r 1`; ladder - same command with `-p 512` and `-ngl 56,48,44,40,36,32`; attempt to run entirely on GPU - `-ngl 99`.

**Artifacts.** /root/runs/V100-154/run.log (attempt -ngl 99), /root/runs/V100-154b/run.log (layer ladder), /root/runs/V100-154c/run.log (context 4096); VRAM peaks in vram.txt, vram2.txt, vram3.txt of the same directories.

**Repeats.** Single run (`-r 1`), dispersion not removed.

**Result.** A single V100 16GB cannot fit: `-ngl 99` fails on allocations of 17,923 MiB (`cudaMalloc: out of memory`), and 56 layers out of 65 load (peak 15,563 MiB), but there's no more space for compute buffers. Limit is 48 layers: with context 4096 pp4096, 455.5 tok/s, tg128 7.43 tok/s, peak VRAM 14,883 MiB. For comparison: IQ3_S on one card gives 35.3 tok/s (V100-31). The V100 plus second-card RPC pool was not measured: it needs `ggml-rpc-server` on the desktop machine, which this run does not occupy.

**Does not show.** The two-machine pool question is not measured: there is no "RPC vs one card" row for Q5_K_M. Quality (MBPP pass@1) not measured, so comparison with 0.60 of IQ3_S not made. Figures taken at context 4096; will be lower at 32k decode.

**Result type.** Mixed

**Verdict.** One 16 GB V100 cannot hold this quantization: the ceiling is 48 of 65 layers at 7.4 tok/s against 35.3 tok/s for IQ3_S on the same card, so the two-machine pool remains the only way to avoid offloading to RAM, and its gain was not measured here.
