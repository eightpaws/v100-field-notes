# V100-119 - Someone else's repository: where to change

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Order work rarely starts from a blank page: it starts inside someone else's project. Before
writing a line, the model has to find where the change belongs. The test: 12 Python files (1,325 lines) taken
from a real project, all pasted into a 32k context in one piece, and 10 tasks phrased the way a customer phrases
them ("add a rights check to the notes output", "change the date format in the API"). The model must name the
file, the function and the line where the change goes, and say why. Criterion: the right file in 7 of 10 tasks;
below that, legacy orders are only taken with a human reading the code first.

**Environment.**

| Item | Value |
|---|---|
| GPU | Tesla V100-SXM2-16GB, compute 7.0, 16 GB, driver 580.178.04 |
| Model | Qwen2.5-Coder-7B-Instruct Q8_0 |
| Engine | llama.cpp build129, CUDA 12.9 |
| Server flags | `-c 32768 --port 18365` |
| Corpus | 12 Python files, 1,325 lines, from the project's `serve/` directory |
| Runtime | Python 3.12 |

**Commands.** Verbatim:

```
/root/bin/v100-run.sh V100-119 -- python3 /root/repo119.py
```

The runner starts `llama-server --port 18365 -c 32768` with the quantized 7B model; the tasks are generated from
the corpus docstrings through `ast`, and the answer is checked with `ast` as well (file name and function name),
so the set is reproducible on any documented repository. Temperature 0.

**Repeats.** `single run`, 10 tasks, temperature 0.

**Result.** The edit point is found:

| Metric | Result |
|---|---|
| Right file | 9 of 10 |
| Right function | 9 of 10 |
| Strict pair (file and function) | **8 of 10** |

The criterion (7 of 10) is met.

Two errors, both informative. In task 5 the model answered `KeepAwake.create` instead of `create`: it is a class
method, so the answer is right in substance and wrong in format, and a human reviewer would accept it. In task 10
it named `runconfig.py` instead of `logit_bias.py`: a function called `validate_request` exists in both files, and
the model picked the file by call context rather than by definition.

**Verdict.** Positive against the stated criterion, with a caveat worth reading before selling it: the 8 of 10 is
a strict string match, so the true hit rate is closer to 9 of 10 once a reviewer accepts method-qualified names.
The remaining failure is semantic, not syntactic - name clones in a repository defeat a model that has only the
docstrings and no call graph.

**Result type.** Positive.

**Does not show.** The ground truth was labelled by hand once and never re-checked, and there is a single run -
no second pass, no temperature variation. The corpus is the project's own code, so naming conventions may help
the model more than a customer's codebase would. The card asked for the line number as well; only file and
function were scored, so line-level accuracy is unknown. No other model was measured on the same set, so this is
a level, not a comparison.
