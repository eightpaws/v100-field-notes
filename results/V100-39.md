# V100-39 — TTFT and model loading with warm cache

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 96 GB RAM, driver 580._

**Hypothesis.** The first run of each model read weights from the disk: page cache could not hold 9–22 GB with 32 GB RAM. With 96 GB, everything is resident, so "14B - 16s load" and all TTFT are overestimated for subsequent runs.

**Test rig.** Tesla V100-SXM2-16GB (cc 7.0, 16384 MiB) · driver 580.178.04 · Ubuntu 24.04.5, kernel 6.8.0-151 · EPYC 7282, 24 vCPU, 94 GiB RAM · Python 3.12.3 · ollama: KV_CACHE_TYPE=q8_0, NUM_PARALLEL=4, KEEP_ALIVE=30m, MAX_LOADED_MODELS=1

**Commands.** Cold and warm start: llama-server (after unloading the page cache) and Ollama 14B (after offload of the model).

**Numbers.**

| engine | state | wall, s | prefill, ms |
|---|---|---|---|
| llama-server | cold | 22.4 | — |
| llama.cpp | warm | 3.2 | — |
| ollama 14B | after unload | 18.225 | 1155.2 (1634 tokens) |
| ollama 14B | warm | 0.197 | 69.5 (whole prefix from cache) |

**Artifacts.** [raw/runs/V100-39.json](../raw/runs/V100-39.json)

**Repeats.** two measurements per engine (cold / warm)

**What is needed.** Ollama and llama.cpp, 14B Q4, cold (after drop_caches) and warm load measurements, TTFT for 1k and 8k.

**How it was verified.** Cold/Warm load time, TTFT. Record both values as a baseline in the 'Test Matrix'.

**Risks.** For the "first launch after reboot" scenario, the old numbers remain valid - it is important to record both numbers, not replace one with the other.

**Result.** A warm page cache changes the picture dramatically. llama.cpp: cold start 22.4 s, warm repeat 3.2 s - 7 times faster. Ollama 14B: after offloading the model, 18.2 s and prefill 1155 ms on 1634 tokens, immediately next 0.2 s and prefill 69.5 ms (entire prefix from cache). Previous figures "14B loads in 16 s" are only valid for the first start after reboot; in working mode, loading is 3 s, and repeat TTFT is practically zero. Both values are entered as a standard.
