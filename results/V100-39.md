# V100-39 — TTFT and model loading with a warm page cache

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Result type.** Positive.

**Question.** Every earlier "loading a 14B takes 16 s" and every TTFT figure was measured while the VM had 32 GB
of RAM and the page cache could not hold 9–22 GB of weights, so each first run read from disk. With 96 GB the
weights stay resident. How much of the old number was disk, and how much is real?

**Environment.**

| Component | Value |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2-16GB, 16384 MiB / 580.178.04 / 7.0 (sm_70) |
| Engines | llama.cpp `llama-bench` / `llama-server`, Ollama 0.40.16 |
| Model | qwen2.5-coder-14b, Q4_K GGUF (`/models/qwen2.5-coder-14b.gguf`) |
| Host | Proxmox VE VM — 24 vCPU (EPYC 7282), 94 GiB RAM, Ubuntu 24.04.5, kernel 6.8.0-151 |
| Cold state | `sync; echo 3 > /proc/sys/vm/drop_caches` before the run |

**Commands** (verbatim from the run script):

```bash
sudo -n sync && sudo -n sh -c 'echo 3 > /proc/sys/vm/drop_caches'

/srv/media/ai-cache/llama-volta/llama.cpp/build/bin/llama-bench \
  -m /models/qwen2.5-coder-14b.gguf -p 1024 -n 8 -ngl 99 -fa 1 -r 1 -o json
```

```bash
# Ollama: unload, then time a 1k-token prompt twice
curl -s http://127.0.0.1:11434/api/generate \
  -d '{"model": "qwen2.5-coder-14b:latest", "keep_alive": 0}'
curl -s http://127.0.0.1:11434/api/chat -d '{
  "model": "qwen2.5-coder-14b:latest",
  "messages": [{"role": "user", "content": "<~1k-token prompt>"}],
  "stream": false, "keep_alive": "10m",
  "options": {"num_predict": 8, "temperature": 0}
}'
```

**Results.**

| engine | state | wall, s | prompt tokens | prefill, ms |
|---|---|---|---|---|
| llama.cpp (`llama-bench`) | cold page cache | 22.4 | — | — |
| llama.cpp (`llama-bench`) | warm repeat | 3.2 | — | — |
| Ollama 14B | after `keep_alive: 0` unload | 18.2 | 1634 | 1155.2 |
| Ollama 14B | immediately after | 0.197 | 1634 | 69.5 |

**Repeats.** Cold and warm measured once each per engine; the point of the card is the ratio, not the precision.

**Verdict.** A warm page cache changes the picture by an order of magnitude: 22.4 s cold against 3.2 s warm for
llama.cpp, and 0.197 s for the repeated Ollama call with the whole prefix coming from cache. The old "14B loads in
16 s" figure is only true for the first run after a reboot — in a working loop the load is ~3 s and the repeat TTFT
is effectively zero. Both numbers belong in a benchmark table; replacing one with the other is what makes
comparisons wrong.

**Does not show.** Does not separate weight loading from harness start: the cold and warm figures are wall times of a whole `llama-bench` invocation, not pure load time. The Ollama pair is cleaner (API call timing) but still one measurement each, and the two engines were not run back to back, so page-cache state may differ.
