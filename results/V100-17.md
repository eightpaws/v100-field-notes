# V100-17 - LMDeploy TurboMind: AWQ without forks

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Linux VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** TurboMind is the only path where sm_70 is not a fork but an officially supported target: AWQ/GPTQ int4 cores built on tensor-core `8x8x4` WMMA. If it works, we get a stable 4-bit server without building foreign branches and without the risk that it breaks tomorrow. The criterion was: not slower than an 8-bit GGUF of the same model, and noticeably more accurate than a 4-bit GGUF because of W4A16 with a group scale.

**Environment.** Tesla V100-SXM2-16GB (sm_70, 16384 MiB), driver 580.178.04, CUDA 12.9; LMDeploy 0.18.0 with the TurboMind backend, torch 2.10.0+cu128 in a dedicated virtualenv; Ubuntu 24.04.5, kernel 6.8.0-151-generic, EPYC 7282 with 24 vCPU, 94 GiB RAM. Model: `Qwen2.5-Coder-7B-Instruct-AWQ`, 5.58 GB in two shards, served with `--session-len 4096 --tp 1`.

**Commands.** `lmdeploy serve api_server <checkpoint> --backend turbomind --model-format awq --session-len 4096 --tp 1 --server-port 18311`, then five requests to `/v1/chat/completions`: `max_tokens=1` on two prompts to time prefill and `max_tokens=256` three times to time decode, all with `temperature=0`. Driver script: `bash /root/bin/v100-run.sh V100-17 -- bash /root/bin/v100-17d.sh`.

**Results.**

| Metric | Value | Unit |
|---|---|---|
| decode, 256 tokens, n=3 | 131.3 ± 0.03 | tok/s |
| prefill, 751-token prompt | 4754.6 | tok/s |
| prefill, 51-token prompt | 241.5 | tok/s |
| VRAM during the run | 14 769 | MiB |
| server start | 50 | s |
| MBPP pass@1, AWQ 4-bit (earlier run) | 0.50 (20/40) | share |
| MBPP pass@1, Q8_0 baseline (other run) | 0.625 (25/40) | share |

**Result.** TurboMind runs on sm_70 and decodes at 131.3 ± 0.03 tok/s with prefill at 4754.6 tok/s on a 751-token prompt, VRAM peak 14 769 MiB and a 50-second server start. The quality side is the price: MBPP pass@1 is 0.50 (20/40) for the 4-bit AWQ checkpoint against 0.625 (25/40) for the same 7B model in Q8_0, so five tasks out of forty are lost.

**Repeats.** Decode n=3: 131.2, 131.3, 131.3 tok/s, mean 131.3 with stdev 0.03. Prefill was measured once per prompt length, no spread. The quality comparison is a single run per quant from the earlier session of this card.

**Verdict.** TurboMind on sm_70 is a fast server - 131 tok/s and a 50-second start - but 4-bit AWQ gives up five MBPP tasks out of forty against Q8_0, so it is a throughput choice, not a replacement for 8-bit where code quality matters.

**Result type.** Mixed.

**Does not show.** The Q8_0 baseline comes from a different run and a different engine, so the speed ratio and the accuracy gap are not like-for-like; no 14B AWQ checkpoint was measured at all; quality was checked only on MBPP and only in Python; how many tasks are lost on real projects is unknown; decode was measured on one prompt with an empty queue.
