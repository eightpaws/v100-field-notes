# V100-140 — Q4_0 KV disrupts generation

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Quantized KV cache q4_0 of 7B provides a coherent response and saves VRAM, making it suitable for enabling long context without output verification. Criterion: a short query (`def add(a, b)`) returns functional code in both modes.

**Environment.** Tesla V100-SXM2-16GB (sm_70), driver 580.178.04, Ubuntu 24.04; llama.cpp build129 (CUDA sm_70); Qwen2.5-Coder-7B-Instruct q4_K_M, context 65536, `-b 512 -ub 512`, port 18480.

**Commands.** Server command: `llama-server -m /srv/media/ai-cache/downloads/qwen2.5-coder-7b-instruct-q4_k_m.gguf -ngl 99 -c 65536 -ctk q4_0 -ctv q4_0 -b 512 -ub 512 --no-warmup --port 18480 --host 127.0.0.1`, then the same launch with `-ctk q8_0 -ctv q8_0` (current unit); request - `/v1/chat/completions`, prompt around 45 tokens, `temperature 0`.

**Artifacts.** srv/media/night/whole_answers.log (answers for q8_0, 20 115 B), /srv/media/night/whole_pkg.log (series for q4_0, 6 tasks, 0 files); publication results/code-loop-whole-package.md.

**Repeats.** Single run per mode: one control query, plus series of 6 tasks on q4_0 and 5 tasks on q8_0.

**Result.** On Qwen2.5-Coder-7B server with `-ctk q4_0 -ctv q4_0`, it produced incoherent text even for a 45 token prompt: `def add,,b):`, with fragments of quotes and arrows. After switching to `-ctk q8_0 -ctv q8_0`, the same query yielded a normal `def add(a, b): return a + b`. Rule: use q4_0 only as a last resort for context length, always follow up with a short control query for coherence; q8_0 maintains 64k on 7B without quality loss.

**Result type.** Negative
