# V100-97 — Batch half-and-half: 20 tasks for both cards

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Independent tasks (file editing + test run) do not require shared memory. If distributed across both GPUs, the total throughput is: V100 7B Q4 - 132 tok/s, PC 7B Q4 - 51 tok/s, resulting in a peak of approximately 1.5x with a 60/40 balance compared to a single V100.

**Environment.** Ollama is installed on both machines, running the same engine: qwen2.5-coder-14b Q4_K_M (9.0 GB) and qwen2.5-coder:7b Q4 (4.7 GB); V100 16 GB (sm_70, driver 580, GPU guest VM, Linux) and 4060 Ti 16 GB (sm_89, Windows, WDDM); the network between machines is not used as each has its own tasks, so 1 Gbps is not a bottleneck.

**Commands.** `python3 /root/v97_worker.py --tasks /srv/media/night/v100_97_tasks.json --ids 0-11 --base http://127.0.0.1:11434 --model qwen2.5-coder-14b:latest --out /srv/media/night/v100_97_splitA_v100.json` and on PC `python v97_worker.py --tasks tasks.json --ids 12-19 --base http://127.0.0.1:11434 --model qwen2.5-coder:14b --out split_A_pc.json`; general start `--start-at <epoch>`, launch on V100 via `/root/bin/v100-run.sh V100-97` with `V100_SKIP_CLEAN=1`.

**Results.**

| Configuration | Tasks V100/PC | Batch Time, s | Speedup | Accepted |
|---|---|---|---|---|
| 14B, one V100 (baseline) | 20 / 0 | 20.46 ± 0.64 | 1.00 | 11/20 |
| 14B, 12 on V100 + 8 on PC | 12 / 8 | 13.38 ± 0.19 | 1.53 | 11/20 |
| 14B, 13 on V100 + 7 on PC | 13 / 7 | 14.59 | 1.40 | 11/20 |
| 7B, one V100 (baseline) | 20 / 0 | 10.62 ± 0.28 | 1.00 | 15/20 |
| 7B, 13 on V100 + 7 on PC | 13 / 7 | 7.43 ± 0.00 | 1.43 | 15/20 |

**Artifacts.** /root/runs/V100-97/run.log; /srv/media/night/v100_97_*.json (base, base7b, splitA, splitB, split7b); PC-halves — /srv/media/night/pc_*.json; tasks — /srv/media/night/v100_97_tasks.json; harness — /root/v97_worker.py.

**Repeats.** 14B - n=3 per configuration (mean ± stdev), 7B - n=3 base and n=2 split; distribution 13/7 on 14B - 1 run.

**Result.** Criterion 1.5x passed only on 14B: distributing 12 tasks on V100 and 8 on PC yields 1.53x compared to one V100 (20.46 → 13.38 s, n=3), on 7B it's 1.43x (10.62 → 7.43 s, n=2). Quality remained unchanged: the set of accepted tasks matched the single-machine run (11/20 for 14B, 15/20 for 7B). The speed ratio sets the ceiling: PC delivers 0.58 of V100's speed (1.60 vs 0.93 s per task), thus a second machine doesn't provide more ~1.6x with any split, and distributing 13/7 is worse (1.40x) - PC is the bottleneck.

**Does not show.** This is not "one model on two cards" (see V100-31) - shared memory and activation exchange were not verified; tasks are short (45-50 response tokens), long responses and file test correction have different startup cost ratios; PC turns off, and then the batch degrades to one V100 without warning.

**Result type.** mixed. **ru** ru× rub (1,53×), rub — 1,43×; ru**What this does not cover.** The two machines run independent tasks, not one model across two cards: shared memory and activation traffic were never tested (that is card V100-31). Responses were short (45-50 tokens), so start-up and scheduling costs weigh more here than they would on long generations. The desktop machine is not a server: when it is off, the batch falls back to a single V100 without a warning.

**Verdict.** Criterion 1.5x passed only on 14B: distributing 12 tasks on V100 and 8 on PC yields 1.53x compared to one V100 (20.46 → 13.38 s, n=3), on 7B it's 1.43x (10.62 → 7.43 s, n=2).
