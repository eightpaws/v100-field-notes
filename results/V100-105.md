# V100-105 — Polyglot: eight languages on one harness

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** This code goes to a client, not into a drawer: it needs several languages, lint cleanliness, security, and middle-sized projects that can actually be delivered and paid for.

**Environment.** Llama.cpp build129 (commit af5c583, CUDA 12.9), V100-SXM2-16GB, driver 580.178.04; models Qwen2.5-Coder-7B-Instruct-Q8_0, DeepSeek-Coder-V2-Lite-16B-Q4_K_M, Qwen3-Coder-30B-A3B-Q4_K_M (`-ncmoe 8`); Python 3.12.3, node v22.11.0, php 8.3.6, ruby 3.2.3, go 1.22.2, javac 17.0.21; `llama-server -ngl 99 -c 4096 --jinja -t 8`, temperature 0.

**Commands.** `/root/bin/v100-run.sh V100-105 -- /usr/bin/python3 /root/polyglot105.py`; llama-server. (Russian note in the field notes is omitted from this English export.)

**Artifacts.** /root/runs/V100-105/run.log; /srv/media/night/v100_105.json; /root/polyglot105.py; --dry. (Russian note in the field notes is omitted from this English export.)

**Repeats.** Single run, temperature 0; Per one request per language per model, spread was not measured - it has no meaning on this set (tasks are solved entirely).

**Result.**

| Model | Languages passing | Assertions (21 per language) | Boot |
|---|---|---|---|
| Qwen2.5-Coder-7B-Instruct Q8_0 | 6/6 | 21/21 in every language | 2.0 s |
| DeepSeek-Coder-V2-Lite-16B Q4_K_M | 6/6 | 21/21 in every language | 30.0 s |
| Qwen3-Coder-30B-A3B Q4_K_M (`-ncmoe 8`) | 5/6 | PHP returned no code block at all | 50.1 s |

Sweep: 6 languages x 10 functions x 21 assertions per language, temperature 0, 3m 04s wall clock.
Syntax was checked by the real compiler (`py_compile`, `node --check`, `php -l`, `ruby -c`, `go build`, `javac`),
not by a parser reading the prompt.

**Verdict.** The 7B Q8 and DeepSeek-V2-Lite pass every assertion in all six languages while the 30B MoE silently drops PHP, so a bigger model is not a safer one - and its boot time is 25x the 7B's.

**Result type.** Mixed.

**Does not show.** One run per model: repeatability and spread were not measured. Only one engine (llama.cpp) was tried. The 3m 04s figure is wall clock for the whole sweep, so per-model latency cannot be derived from it.
