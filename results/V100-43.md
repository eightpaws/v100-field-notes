# V100-43 — llama-server as the working server: prefix cache and batching

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Does llama-server with --cache-reuse actually cut prompt processing for a repeated system prompt, and what does a warm round trip cost compared with the cold one?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-server -m qwen2.5-coder-7b-instruct-q4_k_m.gguf -ngl 99 -fa 0 -c 8192 \
  -b 2048 -ub 512 -ctk f16 -ctv f16 --cache-reuse 256 -np 2 --jinja
```

**Results.**

| Request | Total | Tokens in prompt | prefill | decode tok/s |
|---|---|---|---|---|
| 1 (cold) | 1.18 s | 2067 | 845 ms | 105 |
| 2 | 0.39 s | 9 | 89 ms | 107 |
| 3 | 0.39 s | 11 | 90 ms | 107 |

**Repeats.** three sequential requests with an identical 2067-token system prompt

**Verdict.** Prefix caching works and is the main reason to run llama-server for agent workloads: prompt processing drops from 845 ms to 89 ms (9.5x), round trip from 1.18 s to 0.39 s.

**Result type.** Positive.

**Does not show.** Only one slot count (np 2) and one model were tested; parallel throughput with many clients was not measured. Quantized KV (q8_0) needs flash attention enabled — with -fa 0 the context fails to initialise.
