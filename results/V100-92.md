# V100-92 - PR #31802: fused quantised-KV dequant costs prefill on Volta

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 24 vCPU, 94 GiB RAM._

**Question.** With flash attention the quantised KV cache is materialised as f16 in scratch memory before
the MMA kernel reads it. PR #31802 fuses that dequant into the kernels. Does the prefill at long context
grow by the 15 % the card asks for, or does Volta lose instead?

**Environment.** V100-SXM2-16GB (sm_70). Baseline: our llama.cpp build129 (`af5c583`). PR side: the pull
request head `01eb64f` (`ggml-org/llama.cpp` #31802, still open), built from source with
`-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 -DGGML_CUDA_FA_ALL_QUANTS=OFF`. Model
`Huihui-Qwen3.8-27B-abliterated-GSQ-RCO-IQ3_S.gguf` (10.95 GiB, 26.90 B) - it fits whole, so no expert
offload confuses the comparison.

**Commands.**
```
git clone --depth 1 https://github.com/ggml-org/llama.cpp /root/llama-pr31802
git fetch --depth 1 origin pull/31802/head:pr31802 && git checkout pr31802
cmake -S . -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 -DLLAMA_CURL=OFF \
      -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA_FA_ALL_QUANTS=OFF
cmake --build build -j 16 --target llama-bench llama-cli
llama-bench -m <27B IQ3_S> -p 8192 -n 8 -ctk q8_0 -ctv q8_0 -r 1
```

**Repeats.** One run per build at pp8192 (`-r 1`); the difference is far outside run-to-run noise for
this harness, and decode serves as the internal control.

**Result.**

| Build | pp8192 | tg8 |
|---|---|---|
| baseline build129 | **799.82** tok/s | 35.18 tok/s |
| PR #31802 (`01eb64f`) | **599.35** tok/s | 35.10 tok/s |

Prefill drops by 25 %, decode is unchanged within noise. The card's criterion was +15 % prefill, so the
PR fails it on this architecture.

Practical note for anyone repeating this: the PR tree spends about 90 minutes compiling
`fattn` template instances for sm_70 (three attempts; the run that succeeded used
`GGML_CUDA_FA_ALL_QUANTS=OFF` and `-j 16`). Without that switch the build does not finish in a reasonable
time.

**Verdict.** Negative for Volta: the fused path is slower here, most likely because the 25 % prefill headroom
the PR recovers lives in the tensor-core MMA path, while sm_70 falls to the vector kernel where the extra
fused branch just adds work. The card stays open upstream-wise - the PR may merge and change - but on this
card there is nothing to gain today.

**Result type.** Unstated - the result reports measurements without an explicit pass/fail verdict.

**Does not show.** No profile-level attribution: the drop is measured, not explained by counters. Only
pp8192 was tested (pp16384 did not fit alongside the 27B once KV and prefill buffers were reserved), and
the 30B MoE configuration from V100-51 was abandoned because the model refused to load at that context.
