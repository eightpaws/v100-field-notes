# V100-53 — Cache prefix: equal comparison with equal prompt length

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Upon equal prefix length, cache win will be preserved but reduced; at 12k it will increase because prefill is more expensive.

**Environment.** Llama-server, prefix cache, prompt 8737 tokens in all runs; V100 16GB (sm_70), driver 580, CUDA 12.9

**Repeats.** single run

**Result.** Cache prefix is real and not an artifact of length.** Control with equal prompt length (8737 tokens in all three requests), llama-server with `--cache-reuse 256`, 7B Q4: | Request | Prompt eval | Total | |---|---|---| | Cold | 4154.7 ms | 4.27 s | | Same prefix | **376.6 ms** | **0.42 s** | | Different prefix of **equal length** | 4170.8 ms | 4.71 s | Prefix match speeds up processing by **11x** (4155 → 377 ms), and prompt of same length with different start provides no benefit (4171 ms). Thus, the gain is from cache, not short prompt: for agent cycles where system prompt and history are unchanged, this is the main source of responsiveness.
