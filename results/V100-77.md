# V100-77 - Raon-1-nano: the MTP head exists, the engine does not run it

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 24 vCPU, 94 GiB RAM._

**Question.** The Raon-1-nano GGUF ships in two flavours, with and without a multi-token-prediction
head. If the engine can use that head, speculative decoding comes without a second model. Does a 2 GiB
file buy 15 % decode for free?

**Environment.** V100-SXM2-16GB (sm_70). Upstream llama.cpp cannot open the file at all - the
architecture `raon1nano` is unknown to it. The model runs on `ik_llama.cpp` (build `ac21694`), built
here with `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70`. Files: `raon-1-nano-Q4_K_M.gguf`
(2 082 677 632 bytes, 3.56 B params) and `raon-1-nano-Q4_K_M_MTP.gguf` (2 145 934 208 bytes, 3.61 B).

**Commands.**
```
llama-bench -m raon-1-nano-Q4_K_M.gguf     -p 256 -n 64 -r 3
llama-bench -m raon-1-nano-Q4_K_M_MTP.gguf -p 256 -n 64 -r 3
llama-server -m <file> -ngl 99 -c 4096 --host 127.0.0.1 --port 18490 -t 8 --jinja
curl ... /v1/chat/completions  # 300 max tokens, temperature 0, identical prompt for both files
```

**Repeats.** `llama-bench -r 3` per file; one server generation per file, same prompt, same length.

**Result.** `llama-bench` decode: **84.97 +/- 3.88 tok/s** for the plain file, **63.54 +/- 1.27 tok/s**
for the MTP file - the variant with the extra head is 25 % *slower*, because the head is carried in
memory and never used. Through the server both files behave identically: 212 tokens in 2.5 s, **93.7**
tok/s plain against **92.7** tok/s MTP, and the response carries no draft counters at all
(`draft_n`, `draft_n_accepted` absent). Prefill numbers from `llama-bench` were too noisy to quote
(2673 +/- 1492), so only decode is reported.

**Verdict.** Negative as stated: the MTP head is dead weight on this engine - it costs 25 % decode in
the bench and changes nothing through the server, because no speculative rounds are run. The plain
Q4_K_M file is the one to use at 85 tok/s. Reopen the card when upstream llama.cpp or ik_llama learns
to execute the head; the weights are already on disk.

**Result type.** Unstated - the result reports measurements without an explicit pass/fail verdict.

**Does not show.** Quality: with no MTP execution there was nothing to compare, and MBPP was not run
on either file. Whether the head would help at all on sm_70 (no tensor cores for the draft path) is an
open question, not a measured one.

**Raw.** `raw/runs/V100-77.json` - both benches, both server generations, draft-counter evidence.
