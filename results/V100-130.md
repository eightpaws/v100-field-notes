# V100-130 - Uncensored Flash-Next Q2_0 under Strata

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 94 GiB RAM._

**Question.** V100-83 measured the censored Flash-Next coder at 1 bit and found a model that refuses
nothing but cycles on reasoning. Does the uncensored build in 2 bits behave the same, or does a higher
precision restore the token budget?

**Environment.** V100-SXM2-16GB (sm_70); Strata 0.1.45 with `setup.py --family qwen --model Q2_0
--context 16384`; weights `Qwen3.8-Flash-Next-GSQ-RCO-Q2_0-0000{1,2}-of-00002.gguf`,
37 623 740 192 + 28 800 138 432 = 66 423 878 624 bytes (61.9 GiB).

**Commands.**
```
bash /root/bin/mbpp129.sh            # not used: wrong model, kept for the harness shape
bash /root/bin/run_130b.sh           # starts run-q2_0.sh, then battery + MBPP 200
python3 /root/bin/strata_battery.py --base-url http://127.0.0.1:8080 --label q2abl
python3 /root/code_eval.py --base-url http://127.0.0.1:8080 --model strata --tasks 200 --max-tokens 700 --no-think
```

**Repeats.** Battery and MBPP are single runs; token counts inside MBPP are per task, so the spread is
visible from `avg_sec` rather than from repeated sweeps.

**Result.** The server came up in **90 s** and held **15 661 MiB** of VRAM with the expert cache at
88-90 % hit during the code test. Speed: **45.1 tok/s** during MBPP (1.66 s per task), 38.0 tok/s on a
Russian code prompt, 24.8 tok/s aggregate at four concurrent clients, 14.1 tok/s on a 14-token identity
answer where per-request overhead dominates. Tool calling worked on the first try. Long context found
its needle (5.25 s). **MBPP pass@1 0.51 (102/200)** - statistically the same as the censored 1-bit build
(0.53, 106/200), so 2 bits bought speed, not accuracy.

**Verdict.** The uncensored Q2_0 is a drop-in replacement for the censored coder: same code score within
noise, slightly faster, tool calling works. It answers refused topics and therefore belongs to a personal
loop - never behind a public endpoint, same rule as V100-129.

**Result type.** Mixed: speed and tool calling pass, code quality is unchanged rather than improved.

**Does not show.** No refusal sweep was run on this build, so the abliteration is inferred from the model
family, not measured here. Quality above 2 bits was not compared on the same harness, and the expert-cache
hit rate over long conversations (where it drops) was not tracked.
