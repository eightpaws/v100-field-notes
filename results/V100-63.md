# V100-63 — Model loading is not the same number as harness start

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** The "about 3 s to first token" figure that gets quoted for this rig mixes two different things: reading weights into VRAM, and bringing a serving stack up. Does the second number depend on the engine, and by how much?

**Environment.**

| Component | Version |
|---|---|
| GPU / compute capability | Tesla V100-SXM2 16 GB / 7.0 |
| llama.cpp | master, `build129`, CUDA 12.9, weights read from NFS |
| 1Cat-vLLM | 1.5.4, SM70 kernels |
| Harness | `model_eval.py`, field `start_sec` recorded separately from generation |

**Results.**

| Engine | Model | Start to first token |
|---|---|---|
| llama.cpp master | 7B Q4 | 3.5-4.2 s |
| llama.cpp master | 30B Q4, `ncmoe 16` | 6.1 s |
| 1Cat-vLLM 1.5.4 | 7B GGUF | 105-120 s |

The same model lands twenty-five to thirty times apart depending on the engine. llama.cpp reads weights from NFS and answers almost immediately. vLLM spends roughly two minutes on engine initialisation, memory profiling and graph capture before the first token exists.

That is why the harness records `start_sec` separately from generation: quality blocks are not mixed with start-up cost, and a "3 s" figure is never compared against a stack that needs two minutes.

**Repeats.** single run per engine and model.

**Verdict.** Any load-time number from this rig has to name the engine. For llama.cpp, 3.5-4.2 s for a 7B model is real. For vLLM on Volta the correct figure is about two minutes, paid once per server start rather than per request. Quoting "3 s" for both makes the vLLM card look 30x worse on throughput than it is and hides the actual trade-off: slow to start, faster to batch.

**Result type.** Mixed.

**Does not show.** Only three engine and model combinations, one run each. Cold versus warm page cache was measured in V100-39, not here, so these are cold-start numbers. A second start against an already-warm engine was not measured, and that is where the two-minute cost would shrink.

**Raw.** No archived log for this card: the values were read from the harness field `start_sec` during the session and are not reproducible from a stored file. Treat it as a note, not as a measurement you can re-run.
