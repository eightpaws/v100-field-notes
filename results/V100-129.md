# V100-129 - Uncensored 27B dense on one card

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a VM: driver 580.178.04, CUDA 12.9, 94 GiB RAM._

**Question.** A model is needed that does not refuse gray topics and stays usable. The whole uncensored
Flash-Next family weighs 62-78 GiB and must stream from RAM; the dense 27B at 3 bits is 11.0 GiB and fits
a 16 GB card outright, so the question "does abliteration cost us the model" can be answered in an hour
instead of waiting for a 62 GiB download.

**Environment.** V100-SXM2-16GB (sm_70); llama.cpp build129 for serving (`-ngl 99 -t 8 --jinja`,
context 8192 and 16384, with and without `-fa on`) and build 51831d47 (`/root/llama-old`) for `llama-bench`.
Model `Huihui-Qwen3.8-27B-abliterated-GSQ-RCO-IQ3_S.gguf`, 11 771 546 208 bytes,
sha256 `329e01fc...d3692` matching the HF API.

**Commands.**
```
python3 /root/bin/run_129.py          # decode, prefill, 20 refusal prompts
bash /root/bin/mbpp129.sh             # context 16384 + MBPP 100
bash /root/bin/reeval129.sh           # MBPP 30 with reasoning enabled
bash /root/bin/fa_compare129.sh       # MBPP 40 at ctx 8192, -fa off vs on
bash /root/bin/ctx_compare129.sh      # MBPP 40 at ctx 16384
```
Harness `/root/code_eval.py`; refusal prompts are 10 harmless, 5 gray, 5 clearly harmful.

**Repeats.** Decode `llama-bench -p 512 -n 64 -r 3`: 37.26 +/- 0.01 tok/s. MBPP 40 tasks: two runs at
context 8192 (0.675 and 0.675), one run at 16384 with 100 tasks (0.16) and one at 16384 where the server
never came up (0.0). Refusals: single run.

**Result.** Speed passes: **37.26 tok/s** decode, prefill 837.7 tok/s on pp512 and 800.5 on pp8192; the
server reports 29-33 tok/s per stream during generation, 35.6 on a long one. Code quality passes **only at
context 8192**: `pass@1 0.675 (27/40)`, reproduced twice, with `-fa on` and without, at 34.9 tok/s.
**Context 16384 is unstable**: one launch came up at 12 977 MiB and scored 0.16 (16/100), another never
came up (0 MiB VRAM, pass@1 0.0); without `-fa` the 16k launch died while loading the weights.
Abliteration does what it says: **all 20 refusal prompts were answered**, none refused (10 harmless,
5 gray, 5 harmful).

**Verdict.** Speed and code both pass at 8k, 16k does not hold, and the model answers harmful prompts
outright - it belongs in a personal loop only, never behind a public endpoint. Treat 8k as the working
context for this quant on this card.

**Result type.** Unstated - the result reports measurements without an explicit pass/fail verdict.

**Does not show.** No comparison against the untouched 27B on the same harness, so the size of the
abliteration quality loss is unknown. The 16k failure is not localised: flash-attention kernels on sm_70
and KV-cache size were not separated, and why the first 16k launch came up while the second did not is
unexplained. Russian fluency and long-answer coherence were not scored.

**Raw.** `raw/runs/V100-129.json` - speed and refusal payload, plus MBPP summaries for 8192 (fa off),
16384 (two attempts) and the reasoning-enabled 30-task run.
