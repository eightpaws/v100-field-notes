# V100-44 — NVFP4 on sm_70: 4-bit float in 16 GB

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** In Cat-vLLM 1.5.0, NVFP4 has been added on SM70 (PR #228, #445) - a 4-bit float with pair-wise scaling. At 14B, NVFP4 occupies around 8GB compared to 9.7GB for Q4_K_M, leaving more room for context. To verify: check if the format provides quality gain at the same volume and does not lose speed against GGUF.

**Environment.** vLLM 1.5.4, `--quantization modelopt_fp4`, torch cu128; V100 16GB (sm_70), driver 580, CUDA 12.9

**Commands.** The run script was not preserved; the runner was `/root/bin/v100-run.sh V100-NN`.

**Artifacts.** /srv/media/night/v100_44_nvfp4.log, v100_44_fp4b.log, v100_44_fp4c.log

**Repeats.** single run

**Result.** Works on sm_70. vLLM 1.5.4 (`--quantization modelopt_fp4`) boosted Ornith-1.5-9B-NVFP4 on V100: 14 133 MiB VRAM, decode **86.7-86.8 tok/s** (first request 83.0), code is correct.
