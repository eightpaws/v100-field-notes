# V100-09 — 360° Product: Photogrammetry or Splines

_Measured on a Tesla V100-SXM2 16 GB (sm_70), driver 580.178.04, torch 2.10.0+cu128, CUDA toolkit 12.9 used for the JIT build._

**Question.** A product shot from 20-40 frames on a turntable — can the rig turn it into a 3D model or Gaussian splats, and what does each route cost in time and VRAM? The card was opened on the risk that 3DGS CUDA kernels may not even compile for Volta.

**Test rig.**

| Item | Value |
|---|---|
| GPU | Tesla V100-SXM2 16 GB, compute capability 7.0 |
| Driver / CUDA | 580.178.04 / 12.8 runtime in torch, 12.9 nvcc for the JIT build |
| Splat engine | gsplat 1.5.3, JIT-compiled CUDA extension |
| Photogrammetry engine | pycolmap 4.2.1 (pip wheel) |
| Host | Ubuntu 24.04, EPYC 7282, 94 GiB RAM |

**Commands.**

```bash
export PYTHONPATH=/root/pylibs
export PATH=$HOME/pylibs/bin:<cuda-12.9>/bin:$PATH
export CUDA_HOME=<cuda-12.9>
export TORCH_CUDA_ARCH_LIST=7.0 MAX_JOBS=8 CC=gcc-12 CXX=g++-12
<torch-venv>/bin/python /root/v09_gsplat_bench.py          # 200k Gaussians, 50 iterations
NGAUSS=500000 ITERS=30 <torch-venv>/bin/python /root/v09_gsplat_bench.py
```

Both runs were started through `/root/bin/v100-run.sh V100-09 -- env ...`, which frees the card first and writes the log.

**Repeats.** Single run per configuration (50 iterations at 200k Gaussians, 30 at 500k). No dispersion was measured, so the two points differ by configuration, not by run-to-run noise.

**Result.**

| Configuration | Gaussians | ms/iteration | iterations/s | VRAM peak, MiB |
|---|---|---|---|---|
| 480x640, kernels built in this run | 200 000 | 7.0 | 143 | 98 |
| 480x640, kernels from cache | 500 000 | 9.8 | 102 | 221 |

- JIT build of the CUDA extension for sm_70: **117.9 s**, then **0.9 s** when loaded from the torch extension cache.
- Rendered image is finite and correctly shaped (1, 480, 640, 3), backward pass runs on all five Gaussian tensors.
- Derived, not measured: 30 000 training iterations at 200k Gaussians would take about 3.5 min of rasterization time at the measured 7.0 ms/iteration.
- pycolmap 4.2.1 reports `has_cuda=False`: `patch_match_stereo` and `stereo_fusion` exist in the API but the wheel carries no CUDA kernels, so dense photogrammetry on the GPU needs a source build.

**Verdict.** 3DGS kernels do compile and run on sm_70 (7.0 ms/iteration for 200k Gaussians at 480x640, 98 MiB VRAM), while GPU dense photogrammetry is not available from the pip wheel.

**Result type.** Mixed.

**Does not show.** No product frames were shot, so reconstruction quality, hole count and product recognizability are untested; the dense COLMAP/Meshroom route was not measured at all (only its packaging checked); the video-rendering and encoding steps of a 360° clip were not timed.
