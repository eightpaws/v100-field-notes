# V100-62 — 720p with VAE tiling: check the frames, not just the return code

_Measured on a Tesla V100-SXM2 16 GB (sm_70) in a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Result type.** Mixed.

**Question.** Wan 2.2 5B produced 1280×704 / 97 frames with VAE tiling enabled, but the previous run
returned a decoder warning (`Cannot handle this data type`) and no video file. If tile seams are visible,
"720p works" is the wrong conclusion; if they are not, tiling is a usable way past the 16 GB ceiling.

**Environment.**

| Component | Value |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2-16GB, 16384 MiB / 580.178.04 / 7.0 (sm_70) |
| Model | Wan2.2-TI2V-5B, fp16, 30 steps, guidance 5.0 |
| Stack | diffusers 0.39.0, torch 2.10.0+cu128, cuDNN disabled (no conv kernels for sm_70) |
| Host | Proxmox VE VM — 24 vCPU (EPYC 7282), 94 GiB RAM, Ubuntu 24.04 |
| VAE | `pipe.vae.enable_tiling()`, decoder offloaded, peak VRAM 13.55 GiB |

**Commands** (verbatim from the run script):

```bash
/root/bin/v100-run.sh V100-62 -- /var/lib/ollama/venvs/video/bin/python /root/v100_62.py
# inside the script:
pipe(prompt=..., width=1280, height=704, num_frames=97, num_inference_steps=30, guidance_scale=5.0)
arr8 = (np.clip(np.asarray(frames, dtype=np.float32), 0, 1) * 255).round().astype(np.uint8)
export_to_video([Image.fromarray(f) for f in arr8], out_path, fps=16)
```

**Results.** Generation 903 s, VRAM peak 13.55 GiB, output 97 frames / 6.06 s at 16 fps (187 kbps).
No seams. A per-tile boundary check was run on 25.11 over all 97 frames: mean absolute line-to-line
brightness delta at the tile edges x = 256 / 512 / 768 / 1024 is 0.21 / 1.37 / 3.14 / 1.12 gray levels,
while arbitrary control columns (300 / 600 / 900 / 1150) give 0.26 / 2.10 / 1.41 / 0.39 — tile edges sit
inside the control range and are indistinguishable from normal image content. The one candidate, x = 1024
at 5.13 gray levels, is a smooth ramp rather than a step: its neighbours at x = 1022 / 1023 / 1025 read
4.21 / 4.10 / 3.92. The strongest delta in the frame is row 596 (≈8–10× the median), the tabletop edge in
the scene, confirmed visually. Whole-frame line statistics without a control column are misleading here:
the median delta on smooth background is 0.5 gray level, so any soft gradient scores 5–10× and a "seam"
is reported where there is none.

Two failure causes from the parent run were fixed rather than worked around: (1) the decoder hands back
float32 frames in 0..1, which `export_to_video` rejects, so frames are converted to uint8/PIL first;
(2) on sm_70 `torch.backends.cudnn.enabled` must be `False`, otherwise `conv3d` inside `patch_embedding`
dies with `GET was unable to find an engine to execute this computation`.

**Repeats.** Single run (15 min). The same configuration took 594 s on 22.11; the 903 s reads are not a
repeat measurement, and the 52% spread is unexplained — most likely the VAE decoder running without cuDNN.

**Verdict.** 720p with VAE tiling is viable — no tile seams at 1280×704 / 97 frames on 13.55 GiB. The weak
point is not tiling but overall softness and blown highlights at 30 steps with the 5B model; go to 45 steps
or downscale-and-upscale instead of blaming the tiler.

**Does not show.** Only one seed and one prompt were rendered, and the scene is almost static: the mean
absolute difference between consecutive frames is 0.11 gray levels out of 255, so seam behaviour under
fast motion is untested. Seam visibility on high-frequency textures (fabric, foliage, text) is untested
too, and no non-tiled 720p reference exists — the untitled run OOMs on 16 GB, so "no seams" is compared
against other columns of the same frame, not against a tiling-free render.

**Follow-up completed.** The per-tile boundary check promised on this card was measured on 25.11.2026
over all 97 frames (gradients exactly on x = 256/512/768/1024 against control columns); no tile-periodic
edge exists. The two remaining gaps — fast motion and high-frequency textures — are recorded in the wiki
card as untested; no run for them is scheduled yet.
