# V100-41 — GPT-OSS-20B MXFP4 on a 16 GB Volta card

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** GPT-OSS-20B is a 21B MoE with 3.6B active parameters shipped in MXFP4 (13.8 GB). Does it fit a 16 GB V100, and does flash attention help the way the ik_llama.cpp notes claim for Titan V?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp master 51831d4 (built from source) |
| Runtime | CUDA 12.9.41, GCC 13 host compiler |
| Host | Proxmox VM, 24 vCPU, 94 GiB RAM, Ubuntu 24.04 |
| Model storage | ZFS pool over NFS (4.6 TB free) |

**Commands.**

```bash
llama-bench -m gpt-oss-20b-MXFP4.gguf -p 128 -n 32 -ngl 99 -ncmoe N -fa 0|1 -r 1
```

**Results.**

| Experts on CPU (-ncmoe) | FA | prefill tok/s | decode tok/s |
|---|---|---|---|
| 0 | off | OOM | — |
| 8 | off | 297.8 | 3.04 |
| 16 | off | 205.0 | 1.93 |
| 4 | on | 500.1 | 24.0 |
| 6 | on | 396.7 | 19.8 |
| 8 | on | 331.6 | 16.9 |
| 4 | on + q8_0 KV | OOM | — |

**Repeats.** single run per configuration (loading a 13.8 GB model dominates the wall clock)

**Verdict.** Usable only with flash attention on and 4 expert layers pushed to CPU: 24 tok/s decode. Both faster coding candidates (DeepSeek-Coder-V2-Lite at 183 tok/s, Qwen3-Coder-30B at 75 tok/s) beat it, so it stays out of the working stack.

**Result type.** Mixed.

**Does not show.** Answer quality was not measured: the model spends its first hundred tokens on a reasoning block, and a 120-token budget produced no code at all. The advertised 128k context was not tested — with experts on CPU it would be slower still.
