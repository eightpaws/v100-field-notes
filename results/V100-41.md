# V100-41 - GPT-OSS-20B MXFP4 on a 16 GB Volta card

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** GPT-OSS-20B is a 21B MoE with 3.6B active parameters shipped in MXFP4. Does it fit a 16 GB V100 whole, what does it decode at, and does flash attention help the way the ik_llama.cpp notes claim for Titan V?

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp 1.0.0-dev, build 1224, commit 51831d47 (built from source) |
| Runtime | CUDA 12.9, batch 2048 / ubatch 512, f16 KV |
| Host | Proxmox VM, 24 vCPU (EPYC 7282), 92 GiB RAM available, Ubuntu 24.04, kernel 6.8 |
| Model | gpt-oss-20b MXFP4, 12,096,558,336 bytes (11.27 GiB), 20.91 B parameters |
| Model storage | ZFS pool over NFS |
| GPU state before the run | 0 MiB used, GPU lease taken by the runner |

**Commands.**

```bash
B=/root/llama-old/build/bin/llama-bench
M=/srv/media/ai-cache/downloads/gpt-oss-20b-MXFP4.gguf
# full offload - the configuration this card now recommends
$B -m $M -p 128 -n 32 -r 3 -ncmoe 0 -fa on -o json
# experts pushed to the CPU
$B -m $M -p 128 -n 32 -r 3 -ncmoe 4,8 -fa on -o json
$B -m $M -p 128 -n 32 -r 3 -ncmoe 8 -fa off -o json
```

Each line ran detached through the harness wrapper (`v100-run.sh V100-41 -- <script>`), which cleans the card, takes the GPU lease and writes `/root/runs/<id>/run.log`. A second pass of the same three commands wrote the markdown summaries to the same log.

**Results.**

| Experts on CPU (-ncmoe) | FA | prefill pp128 tok/s | decode tg32 tok/s | peak VRAM |
|---|---|---|---|---|
| 0 (full offload) | on | 1514.50 ± 41.96 | **158.94 ± 0.86** | 11,261 MiB |
| 4 | on | 591.00 ± 15.69 | 90.47 ± 2.24 | not measured |
| 8 | on | 368.85 ± 8.28 | 64.12 ± 0.92 | not measured |
| 8 | off | 364.00 ± 12.29 | 58.61 ± 1.31 | not measured |

**Result.** With every layer on the GPU the model needs 11,261 MiB of the 16,144 MiB card and decodes at 158.94 ± 0.86 tok/s, with prefill of 1514.50 ± 41.96 tok/s at a 128-token prompt. Pushing four expert layers to the CPU costs 43% of decode (90.47 tok/s) and 61% of prefill; pushing eight costs 60% and 76%. Flash attention at -ncmoe 8 is worth 9% of decode (64.12 vs 58.61), not the order of magnitude the previous edition of this card reported. A second pass of the same three commands measured 580.84 / 87.48 / 366.28 / 63.78 / 359.37 / 60.68 tok/s and 1544.25 tok/s prefill - a spread of up to 4% between invocations, so differences below roughly 5% here are noise. Nothing runs out of memory: the previous edition's OOM at `-ncmoe 0` and its 3.04 tok/s without flash attention did not reproduce on the same build (51831d47, build 1224), and the log of that run was never archived, so the cause of the difference cannot be established. For reference on the same card: DeepSeek-Coder-V2-Lite decodes at 183.6 tok/s (V100-47) and Qwen3-Coder-30B-A3B at 75.5 tok/s (V100-45).

**Repeats.** n=3 (`-r 3`) inside every configuration, mean ± stdev reported; the whole set was run twice, which is where the invocation-to-invocation spread of up to 4% comes from. The VRAM peak comes from polling `nvidia-smi` every 2 s during a separate single run of the full-offload configuration (1490.65 / 157.92 tok/s in that run).

**Verdict.** The model fits a 16 GB V100 whole and decodes at 159 tok/s; pushing expert layers to the CPU only loses speed.

**Result type.** Positive.

**Does not show.** Long context is not measured: llama-bench runs at its default context, and a KV cache at 32k or 128k will eat the 4.9 GiB of headroom left by the 11.27 GiB of weights, so the advertised 128k may still not fit. Answer quality on code and on non-English prompts is not measured, so the 159 tok/s figure says nothing about whether the model is worth using. The gap against the earlier 24 tok/s edition is unexplained, because the original log was not archived.
