# V100-11 — System prompt KV cache

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 96 GB RAM, driver 580._

**Hypothesis.** The agent and the store chat have the same long system prompt (2–6k tokens). If the prefix cache lives between requests and sessions, this part is not recomputed: llama.cpp slots/`--prompt-cache` and `cache_reuse`, and for vLLM - prefix caching. This saves 1–4 seconds per request, which is more noticeable in interactive settings than the extra 10 tok/s.

**Test rig.** Tesla V100-SXM2-16GB (cc 7.0, 16384 MiB) · driver 580.178.04 · Ubuntu 24.04.5, kernel 6.8.0-151 · EPYC 7282, 24 vCPU, 94 GiB RAM · Python 3.12.3 · ollama: KV_CACHE_TYPE=q8_0, NUM_PARALLEL=4, KEEP_ALIVE=30m, MAX_LOADED_MODELS=1

**Commands.** `llama-server` with prefix cache and `--cache-reuse`; prefixes ~2k and ~6k, three scenarios: cold, repeat, tail edit. Plus the same test on Ollama.

**Artifacts.** `[raw/runs/V100-11b.json](../raw/runs/V100-11b.json)`, `[raw/runs/V100-11-ollama.json](../raw/runs/V100-11-ollama.json)`

**Repeats.** two launches: the first crashed with `RemoteDisconnected`, the second (11b) produced a result

**What is needed.** llama.cpp server with slots, one stable system prompt, client-script; for the base - Ollama as is.

**How it was verified.** Time to the first token with a cold and warm slot on prefixes 2k and 6k; this gives cache_reuse when editing the latest messages; how it behaves when changing the model.

**Risks.** The cache is invalidated by any change at the beginning of the prompt (date, counter) - the order of fields must be fixed; slots hold VRAM and interfere with parallel requests.

**Result.** The prefix cache works in both llama.cpp and Ollama, but llama.cpp wins on tail editing. 2k prefix: cold 1047 ms, repeat 663 ms, tail edit 95 ms (recomputed 34 tokens). 6k: cold 1106 ms, repeat 186 ms against 1541 ms without cache - an 8x speedup. Ollama on the same prompts: first 967 ms, repeat 199 ms, but tail edit recomputes the entire prefix. Conclusion: enable cache in llama-server, fix the order of fields in the system prompt (date at the beginning breaks everything).
