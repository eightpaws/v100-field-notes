# V100-48 — FIM-autocompletion in the editor

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Autocomplete is the most frequent operation in wai coding, and it should respond faster than chat: goal under 300 ms to the first token. Qwen2.5-Coder can do mid-fill, and prefix cache on V100 is already working (V100-11).

**Result.** Autocomplete via FIM works: llama-server (build llama-volta b7743fbfd8), Qwen2.5-Coder-7B-Instruct Q4_K_M, V100 16 GB, `-ngl 99 -fa 0 -c 4096`, request to `/infill`. Check on a real snippet: prefix `def total_price(items): ... for item in items:` and suffix `return total`. The model completed with `total += item['price'] * item['quantity']` - correct, it took the field name from the context. | Metric | Value | |---|---| | generation | 99.5 tok/s | | prefill | 40.7 tok/s | | request delay | 126-1530 ms, median around 450 | Delay spread is large: the second run gave 1.5 s with the same prompt, the third 126 ms. Looks like the behavior of slot and prefix cache in the old build; for the editor, a run with `--cache-reuse` and one slot is needed. For working in the editor, 100 tok/s is sufficient to complete the line faster than a person types. Delay tuning required. Artifact: `/srv/media/night/v100_48_server.log`.
