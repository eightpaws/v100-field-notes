# V100-49 — Embeddings for code search with bge-m3 on V100

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a virtual machine: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Can this card serve a multilingual embedding model well enough to rank C/C++ source by a
natural-language query, and how much context does a top-5 retrieval save against reading ten whole files?
Success criterion: recall@5, chunk build time, and the ratio of retrieved characters to whole-file characters.

**Environment.**

| Component | Version |
|---|---|
| GPU / driver / compute cap | Tesla V100-SXM2 16 GB / 580.178.04 / 7.0 |
| Engine | llama.cpp 1.0.0-dev, build 1224, commit 51831d4 |
| Runtime | CUDA 12.9, Ubuntu 24.04.5, kernel 6.8.0-151 |
| Embedding model | bge-m3 Q8, 606 MB, pooling `cls`, `-ngl 99 -c 1024 -b 1024 -ub 1024 -t 8` |
| Corpus | C/C++ sources of one inference engine, 257 files, 8.7 MB |
| Chunking | 1400 characters per chunk, 200 characters overlap, 24 chunks per request |

**Commands.**

```bash
# server holds the embedding model; the harness starts and stops it
llama-server -m bge-m3.gguf --embedding --pooling cls \
  -ngl 99 -c 1024 -b 1024 -ub 1024 -t 8 --host 127.0.0.1 --port 18497

# harness: index src/, then ask 30 questions
python3 v100_49.py          # POST /v1/embeddings, batches of 24 chunks
```

| Metric | Value | Unit |
|---|---|---|
| files in corpus | 257 | file |
| index chunks | 6 990 | chunk |

| hit@1 at file level | 0.567 (17/30) | share |

The 30 questions were built from function names that are unique in the corpus, and the expected answer
is the file that defines the function. Seven questions missed: in every case the retriever returned a
sibling file that defines a near-identical kernel (`quantize_q8_1_kernel` resolved to `quantize_act.cu`
instead of `iq_kernels.cu`, `native_swiglu_quantize_q8_1_kernel` resolved to three related CUDA files,
`make_buffer` resolved to a test file instead of the working one). The failure mode is confusion between
near-duplicate definitions, not a lost topic.

**Repeats.** Single run: the index was built once and the 30 questions were asked once. No spread across
repeats was taken, so a difference of two or three questions is inside noise.

**Verdict.** Mixed: recall@5 of 0.767 with 46x less context than reading ten whole files, but near-duplicate
kernels are confused, so a reranker on top of the same index is the next step.

**Result type.** Mixed.

**Does not show.** Questions carry a lexical hint: they are built from function names that appear verbatim
in the target file, so recall on a pure description without any identifier will be lower than 0.767. The
corpus is C/C++ only; Python code was not tested. No reranker was applied, and no comparison against a larger
embedding model was made. Index build time and recall come from a single run.

**Raw.** `raw/runs/V100-49.json` — all 30 questions with the expected file, the top-5 chunks and files with
cosine scores, the per-question rank, and the index parameters.

**Follow-up.** A reranker over the same index and a Python corpus are the next step; queued as V100-49c.
