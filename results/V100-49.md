# V100-49 — Code search embeddings

_Measured on a Tesla V100-SXM2 16 GB (sm_70) inside a Proxmox VM: 24 vCPU, 94 GiB RAM, driver 580.178.04._

**Question.** Half of the "smartness" of an agent is not the model, but what it is given in the context. Local embeddings plus a repository index provide precise search and save context by orders of magnitude: instead of ten full files, only five needed fragments are used.

**Result.** Embeddings for code search on our map are working. llama-embedding from llama.cpp master 51831d4, CUDA 12.9, model bge-m3 Q8 (606 MB), `-ngl 99 -c 512`, default normalization. Sanity check: four texts (three functions and the question "how to calculate the order total by price and quantity"), cosine similarity of the question to each function: | Function | Cosine Similarity | |---|---| | total_price (sum by price and quantity) | **0.643** | | fetch_orders (order retrieval from DB) | 0.501 | | send_email (email sending) | 0.374 | Ranking is correct: the relevant function is first with a noticeable margin, unrelated email sending is last. The 606 MB model handles a Russian query against English code without needing separate translation. Indexing our code will be fast: bge-m3 on 512 tokens calculates in fractions of a second, the entire store and skills repository - minutes. Further, only a vector storage layer is needed (can use sqlite + numpy, no external database). Artifact: /tmp/emb.json on ai-gpu (vectors from run).
